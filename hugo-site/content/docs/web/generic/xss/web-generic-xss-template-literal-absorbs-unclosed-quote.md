## 一句话结论

同一参数被同步拼进两个 JS 字符串输出点、两处之间夹着多行源码时，单/双引号无法跨裸换行吸收中间内容（中间行尾的反斜杠不可控），可在一处输出点用反引号开启模板字面量、由另一处输出点自带的反引号关闭，把两输出点之间的整段代码吸收为字符串；模板闭合后的残码交给 payload 自带的块语句与函数调用（如 `;{$(alert(1),'`）求值执行，完成 XSS。

## 原理

- **双输出点约束**：页面把同一参数回显到 `var px = 'INPUT';` 与 `$('xss').val('INPUT');` 两处，中间隔着 `if (px != "") {` 等源码行。只闭合一处单引号会让另一处多出引号而语法出错；把内容包成字符串又需要跨过中间的整段源码。
- **普通字符串不能跨裸换行**：JS 单/双引号字符串内不能出现未转义换行，跨行必须在每一行行尾加 `\`。两处输出点之间的行尾属于服务端源码，payload 只能控制自己的插入点，无法给中间每一行补反斜杠，因此引号包裹方案必然产生 `SyntaxError: Invalid or unexpected token`。
- **模板字面量可以跨行**：反引号包裹的模板字面量允许裸换行、允许出现单/双引号。同一输入在两处输出点各出现一次，第一处注入的反引号与第二处注入的反引号正好配对，两输出点之间的 `if` 语句、第二次输出等整段代码都成为模板字符串内容。
- **闭合后的残码才是执行点**：模板在第二处输出点关闭后，剩余源码是第二处输出点自带的 `'');`、`}`、`})` 等。payload 尾部只需让这段残码成为合法且会求值 `alert` 的 JS：`;` 结束模板表达式语句，`{` 开启块语句，`$(alert(1),'')` 是一次 jQuery 函数调用——`alert(1)` 作为实参在函数调用前求值执行，返回 undefined 也只会让 `$()` 得到空选择集而不抛错；末尾的 `'` 与源码自带引号拼成空字符串实参。
- **执行不依赖 `${}` 插槽**：本手法触发执行的不是模板插槽表达式，而是模板闭合后由 payload 新增的块语句/函数实参表达式。即使 `$` 或 `{` 部分被过滤，也可换成最短的块内直呼 `;{alert('1`，由 `'1` 与源码尾引号拼出字符串实参。
- **过滤器特征**：示例只按字符黑名单 `><+-*/|&^~!?=` 逐字符拦截，未过滤反引号、花括号、圆括号、`$`、逗号、引号与分号，因此模板路线可行；若符号运算符族未被拦截，也可直接用 `in`/`instanceof` 等在表达式层构造（见关联卡）。

## 触发条件

- 同一请求参数被同步输出到至少两个 JS 字符串字面量中（常见形态：`var x='...'` 与 `$().val('...')` 同时回显）。
- 两处输出点之间隔着多行源码，普通引号字符串无法一次性跨过。
- 过滤规则拦截符号运算符（如 `+ - * / = < > ? !` 等）但未拦截反引号、`{}`、`()`、`$`、`,`、`;`；或只处理引号而未处理反引号。
- 页面已加载 jQuery 时 `$()` 路线可用；否则用 `{alert(...)}` 块语句路线。
- 无严格 CSP（内联脚本可执行）。

## 利用步骤

1. 确认参数被拼进的两个（或更多）JS 字符串位置、两处之间隔着的源码行数，以及引号/反斜杠是否被转义。
2. 在第一处输出点闭合单引号后写入 `;` 与反引号，开启模板字面量；第二处输出点携带的反引号会把模板关闭，使两输出点之间的代码变成字符串。
3. 在第二个反引号之后继续写入残码构造，使第二处输出点之后的源码语法合法且会求值 `alert`：jQuery 在场用 `;{$(alert(1),`，否则用 `;{alert('1` 之类的块内调用。
4. 末尾用引号与源码自带引号配平（如 payload 末字符 `'` 与源码 `');` 组成 `'');`）；被模板吸收的中间代码即使含无效片段也只是字符串，不影响执行点。
5. 在浏览器验证弹窗；若模板闭合位置不对，按输出点数量增加/减少反引号配对。

## 变体与关联

- 变体：模板闭合后的执行载体可换 `{alert('1`、`{$(alert(1),`、`{eval(...)}` 等任意表达式/语句，视过滤器允许字符与页面已有全局函数而定。
- 变体：若反引号也被过滤而符号运算符未过滤，可退回运算符表达式路线（`'*alert(1)*'`、`' in alert(1) in '`），见 [[web-generic-xss-operator-expression-injection]]。
- 关联：[[web-generic-xss-javascript-context-injection]]（JS 字符串闭合、表达式位置与 `${}` 插槽基础；本卡处理的是“模板字面量吸收两输出点之间的多行代码”，与 `${}` 插槽不是同一动作）；[[web-generic-xss-json-eval-backslash-escape]]（反斜杠转义对抗）；[[web-generic-xss-script-tag-html-comment-double-escape]]（一处在 JS 一处在 HTML 时先用 `<!--<script ` 把 HTML 输出点变成 JS，后半段可复用本卡的模板吸收思路）。
- 双输出点背景：本卡与“同一参数在 JS 与 HTML 各输出一次”的另一类场景共享“同步双回显”前提，本卡只负责两个输出点都在 JS 内的情况。

## 检测与防御

- 检测：同一参数在响应中出现两次且都落入内联脚本；请求含反引号（`%60`）、`{`、`$(`、`alert(` 的组合。
- 防御：不要拼接生成 JS，改用 `JSON.stringify`/`json_encode` 输出数据；对 `<`、`>`、`&`、`'`、`"`、反引号与 `${` 做 JS 上下文编码，而不是符号黑名单；启用禁止 `unsafe-inline` 的 CSP。
- 局限：依赖两处输出点都未处理反引号且模板能在预期位置闭合；若服务端同时转义反引号或 CSP 严格，则失效。
