## 一句话结论

红星OS（Red Star OS）会在本机打开/处理过的文件末尾追加数字水印：24 字节加密的磁盘序列号、4 字节长度/签名字段（单层为 0x18，叠加后为 0x30 等）以及 ASCII `EOF`（`45 4F 46`）结束标识；同一台机器水印相同、不同机器不同、水印可叠加。用 `redstar-tools` 的解密脚本可还原出磁盘序列号，从而把泄露文件归因到具体机器；反过来，截断文件尾也能剥离水印做反取证。

## 原理

- **水印写入时机**：红星OS 在用户打开/查看文件（如用图片查看器打开 PNG）时，会把当前硬盘设备的序列号加密后追加到文件末尾；原始内容不变，因此文件仍能被正常打开，但哈希值会改变。文章对比同一张图片在 Windows/Linux 下打开前后哈希一致，而在红星OS 打开后 MD5 改变，说明这是系统层自动行为而不是应用层另存。
- **水印结构**（按文章实测的尾部字节归纳）：
  1. **24 字节（0x18）加密数据**：实际上是加密后的磁盘序列号，同一台机器上写入的多份水印字节相同；
  2. **4 字节长度/签名字段**：记录写入数据的长度，单层水印处为 `18 00 00 00`，最大值可为 `FF FF FF FF`；
  3. **ASCII `EOF`（`45 4F 46`）**：文件结束标识，位于追加数据末尾。
- **为什么可以叠加**：把同一文件在不同红星OS 机器（或不同磁盘序列号的虚拟机）上分别打开，每台机器都会追加一份自己的水印；实测两份水印叠加后长度字段变为 `30 00 00 00`（0x30=48），即 2×24 字节，EOF 仍在最后。由此可推断水印按层追加，层数体现在长度字段上。
- **为什么能归因**：磁盘序列号对每台机器唯一，加密写入后只有持有解密脚本/密钥的一方能把 24 字节还原为序列号；执法或取证方拿到泄露文件即可比对是哪台机器产生的水印。
- **为什么可以反取证**：水印是追加在文件末尾的独立数据块，不影响原始格式解析；知道结构后可以按层截断（从最后一层水印前的原始文件结束处截断），恢复原始哈希与内容，从而去除机器指纹。再次在红星OS 打开又会重新写入。
- **限制**：文章没有逆向加密算法本身，解密依赖现成工具；结构判断基于实测字节，不同版本的红星OS 水印长度/字段可能有差异，跨版本需重新核对。

## 触发条件

- 文件曾在红星OS 环境中被打开或处理过（本机文件或插入的 USB 存储设备上的文件）。
- 文件尾部存在附加数据；对图片等格式，附加数据通常不影响打开。
- 需要 `redstar-tools`（含 decrypy/wm_decrypt 脚本）或等价解密实现来还原磁盘序列号。
- 反取证场景需要能写文件、知道原始文件结束位置；若原始文件已被多次水印覆盖，需按长度字段逐层剥离。

## 利用步骤

1. **发现水印**：计算文件哈希，与已知原始副本对比；若 MD5/哈希不同但文件可正常打开，检查文件尾部是否多出数据。
2. **识别结构**：用十六进制编辑器查看文件末尾，定位 ASCII `45 4F 46`（EOF）；EOF 之前 4 字节为长度字段（如 `18 00 00 00` 或 `30 00 00 00`），再往前按长度字段指示的字节数读取一至多份 24 字节水印块。
3. **验证归属**：同一台红星OS 机器上打开多个文件，尾部水印应相同；不同机器/虚拟机的磁盘序列号不同，水印不同且可叠加。
4. **解密归因**：用 `redstar-tools` 的解密脚本处理带水印文件，输出磁盘序列号/标识（实测输出形如 `b'WM3_...'`、`b'WM:...'`）。
5. **反取证（如需要）**：按长度字段计算每层水印起点，截断到原始文件结束位置，恢复原始哈希；注意不要再次在红星OS 中打开该文件。
6. **记录**：保存原始哈希、尾部 hex、解密输出与机器对应关系，作为取证/归因证据。

## PoC

原文使用现成工具解密（原文正文写作 decrypy.py，截图实际执行的是 wm_decrypt.py，以工具仓库脚本名为准）：

```bash
python wm_decrypt.py 红星.png
```

实测输出包含 `b'WM3_...'`、`b'WM:...'` 形式的标识；水印尾部结构示意：

```text
... 原始文件数据 ...
<24 字节加密磁盘序列号>
18 00 00 00                 # 单层长度 0x18（叠加两层为 30 00 00 00）
45 4F 46                    # ASCII "EOF"
```

## 变体与关联

- **多层水印**：同一文件在不同红星OS 机器上多次打开会产生多份 24 字节水印，长度字段递增（0x18 → 0x30 → …）；剥离时需逐层处理。
- **不同文件类型**：文章以 PNG 演示，水印是文件尾追加，对 JPEG/文档等同样可能生效；若格式有严格长度校验，追加可能导致打开异常。
- **归因与反取证**：取证方用尾部水印和磁盘序列号做机器归因；被取证方可用截断/重建文件的方式去除水印。

## 检测与防御

- **取证检测**：对来自高风险来源的文件做尾部 hex 扫描，匹配 `45 4F 46` + 前置长度字段 + 24 字节高熵数据的组合；与已知原始副本做哈希比对。
- **归因**：解密水印得到磁盘序列号，与扣押设备/镜像的磁盘序列号比对，建立文件—机器对应关系。
- **反取证防护**：发布文件前在非红星OS 环境重新导出/截断尾部；注意镜像/备份中仍可能保留带水印副本。
- **防御视角**：红星OS 的水印是泄露追踪机制；跨组织交换文件时应意识到对方系统可能写入机器标识，必要时在隔离环境处理。
