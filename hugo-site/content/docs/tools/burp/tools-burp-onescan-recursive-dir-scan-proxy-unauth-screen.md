## 一句话结论

OneScan 这类 Burp 递归目录扫描插件的价值不在“字典更大”，而在三点可复用的工程化能力：(1) 把每个字典项在请求路径的**每一级目录**上各拼接一次，让深层目录下的隐藏接口/Swagger 文档一并被枚举；(2) 通过“监听代理请求”把登录态浏览产生的真实流量当种子自动扫描，无需手工逐个 send；(3) 扫描前用“移除请求头”“替换请求头”把请求包里的 `Cookie`/`Authorization` 摘掉或换成另一个账号的凭证，再比较响应，从而把“只曝露文档”升级为“未授权/越权是否真的可调”的批量初筛。此外，扫描器通常只发 GET，需用“请求包处理”规则把 GET 改写成 POST 并补 `Content-Type`，否则所有只接受 POST 的隐藏接口都会在前置判断上漏掉。

## 原理

- **递归拼接放大覆盖率**：普通目录扫描器把字典拼在根路径（`/swagger.json`）或用户给定的一个前缀上；递归扫描器会把每个字典项分别拼到已知路径的每一级（`/`、`/a/`、`/a/b/`、`/a/b/c/`），因此同一份字典在深度 d 的目录下产生 d+1 组候选路径。深层目录（尤其是微服务网关后面的 `/api/v1/x/y/`）正是隐藏接口与旧版调试端点最常出现的位置，命中率提升来自“路径深度组合”，不是字典条目数。
- **动态变量降低字典维护成本**：字典里可用目标自身的语义变量（如 `{{domain}}`、`{{domain.main}}`、`{{subdomain}}`、`{{webroot}}`）以及日期变量（`{{date.yy}}_{{date.MM}}_{{date.dd}}.log`）在运行时展开。备份包名、日志文件名通常由域名与当天日期组成，动态展开后能用很短的小字典覆盖大量真实命名规律。
- **被动扫描用真实流量当种子**：插件监听 Burp 代理，把浏览器访问产生的请求路径作为起始节点继续递归扫描；配合主机允许/阻止列表（黑/白名单）限定范围。这样扫描路径天然落在站点真实路由前缀上，比纯字典盲扫的请求数少、命中率高。原文明确：主动扫描发出的请求不受主机允许/阻止列表约束（只有被动扫描受列表过滤），所以主动扫描时更要注意范围控制。
- **摘头/替头为什么能筛出未授权与越权**：大量框架的鉴权只在中间件/过滤链里做，一旦某个控制器被标记为免登录、或某条路由未纳入拦截器，后端仍会正常处理“无凭证”请求。把代理流量里的 `Cookie`、`Authorization` 等凭证整体移除后重放，若响应仍返回业务数据（而不是 401/302 跳登录），说明该接口事实上未做认证。同理，把请求头替换成 B 账号的凭证后用自己的 A 账号流量重放，若 A 上下文拿不到但 B 的凭证能拿到、或 B 的凭证能读到本不属于 B 的资源，就是越权信号。原文给出的实战姿势是：打开“监听代理请求” + “移除请求头”（或“替换请求头”），用 A 账号登录目标站点并把功能过一遍，再在插件里集中看哪些请求摘头/替头后仍返回 200。
- **判据要落在响应差异上**：摘头/替头后不能只看状态码。常见假阴性是前端路由返回 200 的 SPA 兜底页、公共 404 页面、通用错误码；因此需要过滤条件（原文的看板支持按状态码、响应长度、指纹关键字过滤，例如只保留“状态码非 -1 且指纹不含 waf”的条目）以及人工复核响应体是否真含业务数据。
- **请求包处理补足方法差异**：扫描器为省成本只发 GET。若目标接口是 `POST /api/user/list`，GET 会得到 405/404，会被当成“不存在”。用“条件检查 + 匹配/替换 + 添加后缀”这类规则链把请求行 `GET /` 改成 `POST /`、删掉原有 `Content-Type`、追加 `Content-Type: application/x-www-form-urlencoded`，扫描请求就会以 POST 发出，从而命中只在 POST 上注册的接口。
- **为什么仍是“初筛”而非证明**：摘头重放命中 200 只说明“该路由在当前方法/路径下不要求认证”，还需确认响应含真实数据、且操作型接口在无凭证下确实产生状态变更，才能定性为未授权访问；替头命中需确认 B 与目标资源之间本无权属关系。

## 触发条件

- Burp Suite 已安装该插件（新版本 HaE 依赖 Montoya API，需 Burp >= 2023.12.1；低版本 Burp 需配 HaE 2.6.1 一类旧版）。
- 只对授权范围内的目标扫描；有主机允许/阻止列表可限制被动扫描范围。
- 已有一个可登录的账号（做未授权/越权初筛必须先生成带凭证的真实流量）。
- 做越权测试时另需一个不同权限的账号或其凭证（用于“替换请求头”）。
- 目标存在可枚举的深层目录、隐藏接口文档（`/v2/api-docs`、`/doc.html`）或仅在 POST 上注册的接口。

## 利用步骤

1. **安装与初始化**：Burp → Extensions → Installed → Add → 选择插件 JAR；加载成功且无报错即完成。按需把 HaE 的 JAR 路径填进插件“其他配置”的 HaE 项（插件内加载的 HaE 只影响插件自身的高亮，不会干扰 Burp 已装的 HaE）。
2. **配置字典**：使用“隐藏接口文档”“隐藏 API”“敏感信息泄漏”三类字典；敏感信息类字典里加入动态变量（域名、主域名、子域、webroot、当日日期）以覆盖备份包与日志命名。
3. **限定范围**：在插件配置 → 主机配置里维护允许列表（如 `*.target.com`）与阻止列表（公共域名），避免被动扫描把第三方 CDN/统计域名也扫一遍。
4. **主动扫描单包**：在看板打开“目录扫描”，把目标请求 send 到插件；若配了多套字典可选用其它字典。观察结果表里的 `来源=Scan` 行与请求路径，确认逐层拼接效果（如 `/a/b/testxxxx`、`/a/testxxxx`、`/testxxxx` 同时出现）。
5. **被动扫描**：同时打开“监听代理请求”与“目录扫描”，浏览器以真实账号访问允许列表内的目标并过一遍功能；插件对代理流量逐条发起递归扫描。
6. **未授权初筛**：在插件配置 → 请求配置里把要摘除的头填成列表（如 `Cookie`、`Authorization`），回到看板打开“移除请求头”，再重放/被动收集一遍；过滤条件设为“状态码非 -1”“指纹不含 waf”，逐条看返回 200 且含业务字段的条目。
7. **越权初筛**：把请求配置换成 B 账号的完整头（如 `Cookie: user=testB`、`Authorization: Bearer <B 的 token>`），打开“替换请求头”，用 A 账号登录并过功能，再筛“A 的路径 + B 的凭证仍返回业务数据”的条目。
8. **方法改造**：若怀疑目标只在 POST 注册接口，进“请求包处理”新建规则（例如命名 `Post`），依次加：条件检查（生效范围=请求头，正则 `GET /`）→ 匹配替换（`GET /` → `POST /`）→ 匹配替换（删除 `\r\nContent-Type: .*\r\n`）→ 添加后缀（追加 `\r\nContent-Type: application/x-www-form-urlencoded`）；启用规则后重扫，结果表会出现 `来源=Process (Post)` 的 POST 请求。
9. **人工确认**：对每条候选补做“无凭证直连”“差异账号对比”“操作后回查数据是否真的变更”，排除 SPA 兜底页与公共错误页后再定性。

## PoC

无漏洞 PoC（本卡是工具化测试流程）。可复用的最小请求改造规则链（插件“请求包处理”，四条规则按顺序生效）：

```text
1) 条件检查   范围=请求头  正则: GET /
2) 匹配/替换  范围=请求头  正则: GET /   替换为: POST /
3) 匹配/替换  范围=请求头  正则: \r\nContent-Type: .*\r\n   替换为: \r\n
4) 添加后缀   范围=请求头  后缀: \r\nContent-Type: application/x-www-form-urlencoded
```

## 变体与关联

- 变体：不用插件也能复刻“摘头重放”——Burp Repeater 手工删 `Cookie`/`Authorization` 后重放；或用代理脚本对匹配主机的请求自动删头。插件只是把这个动作批量化了。
- 变体：越权方向不止“替头”，还可“同时保留两套会话做响应比对”，与多会话权限矩阵思路一致（见关联卡）。
- 变体：字典变量可扩展为目标自定义信息（产品名、内网域名、Git 提交短哈希等），让备份包/日志名命中率更高。

- 关联：[[web-generic-auth-403-resource-suffix-path-dictionary-bypass]]（扫描出 403 后如何用后缀/分号/编码路径绕过）。
- 关联：[[web-generic-auth-multi-session-matrix-leakscore]]（多会话权限矩阵与评分，把“摘头/替头”的人工初筛升级为可量化流程）。

## 检测与防御

- 检测（防守方视角）：同一源 IP 在短时间内对同一主机发起大量 404、路径逐层递增（`/a/`、`/a/b/`、`/a/b/c/` 同后缀）且带相同 `User-Agent` 的请求，是递归扫描的强特征；请求序列里同时出现 `GET` 与紧随其后的同路径 `POST`（方法改造规则）更典型；摘头测试的特征是同一 URI 在极短时间内先带 `Cookie`/`Authorization`、再不带的成对请求。
- 检测：告警“无凭证请求返回 200 且响应体含业务字段/敏感字段”的组合——这是未授权接口最直接的线上信号，应在网关层开规则而不是只靠人工。
- 防御：统一鉴权中间件并默认拒绝（deny-by-default），不要依赖“控制器上忘了加注解就不拦”；把接口清单纳入 CI 校验（新增路由必须有鉴权声明）。
- 防御：对 `/v2/api-docs`、`/doc.html`、`/actuator`、`/jolokia` 等文档与运维端点在网关层默认 404/401；不要只在“删了 UI”后保留 JSON 端点。
- 防御：越权侧做资源级鉴权（每次读取/修改都校验资源归属），而不是只校验“是否登录”；对同一账号跨租户/跨部门的数据访问做审计。
- 防御：给代理/网关加请求方法一致性校验与速率限制，递归扫描类流量可被限速或挑战验证；备份包与日志文件不要放在 Web 根目录。
