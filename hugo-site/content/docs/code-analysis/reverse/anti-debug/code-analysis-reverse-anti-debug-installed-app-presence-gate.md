## 一句话结论

与其检测 VMware/VBox 痕迹（沙箱很容易伪造成“物理机”），样本改为检查“目标用户一定会装、而分析环境通常不会装”的那一款软件——例如检查系统里是否安装了 Telegram，装了才继续释放后续载荷，没装就立刻退出。这样沙箱即使把虚拟化特征抹干净，只要镜像里没有这款软件，样本就永远走不到恶意分支；代价是对没装该软件的真实用户直接失效。

## 原理

- **判据换成“业务软件存在性”**：虚拟机检测看的是硬件/驱动/注册表中的虚拟化痕迹，这些都能被沙箱伪装；而“某款通信软件是否安装”反映的是镜像的使用者画像，沙箱不做伪装就很难满足。
- **存在性与否直接决定分支**：样本在入口处先做该检查，命中“已安装”才进入后续的解密与释放流程；未命中则静默退出，沙箱侧只会看到一次无行为的短命进程，无法采集解密后的载荷、外联与持久化。
- **判定方式通常是文件系统/注册表查询**：常见做法是查该软件的安装目录（`%APPDATA%`、`%LOCALAPPDATA%`、`Program Files` 下的固定子目录）、查卸载项注册表键，或用 `GetFileAttributes` 判断关键文件是否存在；也可能枚举进程看是否正在运行（进程在跑才更强地说明是活跃用户机）。
- **为什么选“单一应用”而不是白名单**：白名单（QQ/微信/钉钉任意一个在跑）在干净的真实主机上容易全部缺失，误杀率高；只要求单一款软件时，攻击者可以按投放渠道精准选择（如通过 Telegram 群/频道投放就要求 Telegram 已安装），命中率与画像一致性都更好。
- **与“失陷标记文件”的区别**：标记文件（如 `C:\ProgramData\1.txt`）用于避免重复运行或识别已感染机器；本手法读取的是既有商业软件留下的痕迹，用于区分“真实用户”与“分析环境”，两者目的与位置都不同。

## 触发条件

- Windows 目标，检查代码位于任何解密/注入/外联动作之前。
- 沙箱/分析镜像中没有目标软件（常见的干净云沙箱即为如此），或该软件的安装痕迹不足以被误判为已安装。
- 攻击者能按投放渠道预判受害者会安装哪款软件（通信类、办公类、游戏平台等）。
- 攻击者接受“未安装该软件的用户不感染”的漏杀。

## 利用步骤

1. 选定与投放渠道匹配的软件（示例场景为 Telegram），确认其安装痕迹路径固定、在分析环境中默认不存在。
2. 在入口处实现存在性检查：查典型安装目录下的关键子目录/可执行文件、查卸载注册表项、必要时枚举进程确认是否在运行；三项可组合提高判据强度。
3. 检查失败即走退出分支（`ExitProcess`/正常返回一个无害结果），不留下解密、分配可执行内存、外联等可观测行为；也可改为进入一段无害的伪装业务逻辑。
4. 检查通过再执行后续阶段（远程拉配置 → 下载模块 → 白加黑加载 → 解密数据 → 执行 shellcode 一类的完整加载链）。
5. 分析侧对策：在分析镜像里预装该软件或其目录/注册表痕迹，或直接 patch 该检查函数的返回值，使样本进入恶意分支；只改一处时要注意样本可能同时检查目录、注册表与进程三处。
6. 若同时存在虚拟机检测、时间加速检测等多重判据，必须逐个满足或逐个 patch，单点绕过通常不足以让样本跑完整个链。

## PoC

```text
判定逻辑（示意，具体 API 因样本而异）：

  if (!app_installed("Telegram"))      // 查目录 / 查卸载注册表 / 查进程
        ExitProcess(0);                // 静默退出，沙箱看不到后续行为
  else
        run_loader_chain();            // 拉配置 → 下载模块 → 白加黑加载 → 解密执行

分析侧绕过（任选，通常需要同时满足多处检查）：
  1) 在分析镜像中创建该软件的安装目录与卸载注册表项（伪造“已安装”）
  2) 调试器里把检查函数返回值 patch 成 1（已安装）/ 直接跳过条件跳转
  3) Frida hook 对应的文件/注册表/进程查询 API，返回“存在”
```

## 变体与关联

- **判据载体变体**：安装目录、卸载注册表项、开始菜单快捷方式、进程列表、最近使用记录；越贴近“真实用户行为”的载体越难被沙箱伪造。
- **软件选择变体**：通信类（Telegram/QQ/微信/钉钉）、办公类（WPS/Office）、游戏平台（Steam）、输入法（搜狗）——按投放渠道选择。
- **组合判据**：单一软件存在性 + 屏幕分辨率/时区/语言 + 时间加速检测 + 虚拟机痕迹，任一不满足即退出。
- **关联**：[[code-analysis-reverse-anti-debug-common-app-process-whitelist]]（同一目标的“白名单全缺失才退出”形态，靠 `CreateToolhelp32Snapshot` 枚举进程；本卡是“单一软件必须存在”的存在性查询）、[[code-analysis-reverse-anti-debug-silverfox-installer-vm-detection]]（vmGuestLib/WMI 热区/磁盘容量这类虚拟机痕迹判据）、[[code-analysis-reverse-anti-debug-file-marker-remotedebugger-av-process-enum]]（文件标记与进程枚举的组合）。
- **边界**：分析镜像恰好预装了该软件时判据失效；软件改名/换路径/用便携版时存在性检查会否；样本若把检查结果与后续 C2 上报绑定，patch 后行为可能与真实感染链不一致。

## 检测与防御

- **检测（主机）**：新进程在启动早期大量访问其他软件的安装目录与卸载注册表项（尤其与自身功能无关的软件），随后立刻退出或转入解密/注入行为；`GetFileAttributes`/`RegQueryValue` 对多个软件路径的批量探测。
- **检测（沙箱运营）**：在分析镜像中预置常见桌面软件痕迹（目录、注册表、快捷方式），并对“进程启动后秒退且无网络行为”的样本自动重跑，避免被单点判据骗过。
- **防御（终端）**：对短命进程 + 敏感 API 调用组合（创建可执行内存、白加黑模块加载）做行为拦截；限制从用户可写目录加载 DLL（本类样本的后续阶段依赖白加黑）。
- **威胁情报**：把“要求特定软件已安装”作为家族/投放渠道的画像特征，与样本签名证书、C2 配置一起用于关联同批次的钓鱼投放。
