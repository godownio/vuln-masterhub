## 一句话结论

已经定位到人物血量等任一属性的指针链后，不必对每个新属性都从零值扫描：沿着同一条基址/偏移链保留前几层，用数据遍历工具枚举最后一两级偏移，即可在相邻地址找到最大血量、最大蓝量、人物 ID 等结构体字段；若目标字段来自堆栈而非静态结构，再用访问断点沿 `[esp+xx]` 参数逐层回溯到基址。

## 原理

- 游戏角色属性通常集中在同一个角色结构体/对象里：当前血量与最大血量、当前蓝量与最大蓝量、人物 ID/名称等字段相邻。找到一个字段的指针链，就找到了该结构体的入口，邻近偏移很可能就是相关字段。
- “数据遍历”是把已知链的前几层固定，对最后一两级偏移做区间枚举：例如固定 `base → +0x24 → +0x8 → +0x324 → +0xC8 → +0x10`，把最后的偏移从 0x2A0 逐段扫到 0x350，观察每个候选地址的值。识别依据是语义而非地址：
  - 满血/满蓝时当前值与最大值相等；
  - 最大值在受伤/耗蓝时保持不变；
  - 人物 ID 与角色名/账号存在稳定对应关系。
- 枚举可以暴力做几十上百次：没有命中就换下一层或扩大偏移范围，成本通常低于重新做一次完整值扫描 + 断点回溯。没有结果再回退到老方法。
- 堆栈类字段（如人物 ID 由调用参数传入）无法直接在结构体偏移里找到。做法是对已定位地址下访问断点，命中后看 `[esp+xx]`，用调试器右下角堆栈区判断它是第几个 call 参数；按返回地址回到调用者，找该参数的 `push`/寄存器来源，逐层向上。
- 每回溯一层都要用数据语义校验（例如该处必须是人物名称/ID 的字符串），否则容易追到同名临时变量或无关调用。遇到 `call eax` 虚函数调用时，`ecx` 往往是对象指针（thiscall），继续追 `ecx` 的来源（常见来自 `ebp`），最终可回到模块基址。
- 最终得到的表达式是“模块基址 + 多级偏移 + 数组索引”，地址与偏移只对当前游戏版本有效；更新后需重新验证。

## 触发条件

- 目标为 32 位 Windows 游戏/应用，角色属性在用户态内存中以结构体/对象 + 指针形式存在。
- 已能使用 Cheat Engine 附加并读写内存，能用 x32dbg（或同类调试器）下断。
- 已定位至少一个字段（如血量）的基址与偏移；或能通过值扫描先找到一个字段。
- 目标未启用会阻止附加/断点的强反调试，或已绕过。
- 能正常操作角色（受伤、耗蓝、查看角色信息）制造可控值变化。

## 利用步骤

1. **先拿一个锚点**：按血量/蓝量的当前值做 CE 值扫描，改变后重搜，锁定地址并回溯出基址 + 偏移链。
2. **固定前几层**：在 CE 指针编辑器/数据遍历工具中填入已知链，保留 `base → +0x24 → +0x8 → +0x324 → +0xC8 → +0x10` 这类前缀。
3. **枚举末级偏移**：对最后一两级偏移做区间扫描（如 0x2A0–0x350），记录每个候选的值；按“当前=最大（满状态）”“最大值不随消耗变化”“ID 与角色名对应”筛选。
4. **验证字段**：改变游戏内状态（受伤、耗蓝、切换角色），确认候选值随预期变化；对 ID 类字段用角色名/账号交叉核对。
5. **堆栈字段回溯**：若遍历不到，对已知地址下访问断点；命中 `mov eax,[esp+2C]` 一类指令后，在堆栈区确认参数序号，回到返回地址找参数来源；继续向上追 `[esp+24]`、`[esp+1C]`，遇到 `call eax` 虚调用时追 `ecx` 对象指针及其来源。
6. **形成最终链**：把每层 `[reg+offset]` 串成表达式，用 CE 指针编辑器验证；对数组元素补 `+index*4`。

## PoC

示例（32 位，地址/偏移仅对该版本有效）：

```text
# 已知角色结构链前缀
base = xajh.exe+0x11282D8   # 运行时等价 0x15282D8

# 数据遍历：固定前 5 层，枚举末级偏移
[[[[[base]+0x24]+0x8]+0x324]+0xC8]+0x10]+0x2FC = 11122   # 当前/最大蓝量候选
[[[[[base]+0x24]+0x8]+0x324]+0xC8]+0x10]+0x310 = 11122
[[[[[base]+0x24]+0x8]+0x324]+0xC8]+0x10]+0x304 = 12012
[[[[[base]+0x24]+0x8]+0x324]+0xC8]+0x10]+0x2BC = 46468   # 最大血量候选
[[[[[base]+0x24]+0x8]+0x324]+0xC8]+0x10]+0x2D0 = 46468

# 人物 ID 经堆栈回溯后的最终链
[[[[base]+0x24]+0x8C]+0x4B0]+0x0
```

```text
# 堆栈回溯路径（示例）：
# 访问断点命中 mov eax,[esp+2C]
# -> [esp+2C] 为某 call 第 1 个参数，返回上层
# -> [esp+24] -> [esp+1C] -> call eax 虚函数
# -> ecx == 0x45DA00B0（对象指针），ecx 来自 ebp
# -> sub_4AE400: mov eax,[0x15282D8]; mov eax,[eax+0x24]; mov eax,[eax+0x8C]; ret
# -> 再取 +0x4B0、+0x0 得到人物 ID
```

## 变体与关联

- 变体：没有数据遍历工具时，可在 CE 指针编辑器里手动逐个改末级偏移并观察值，或用脚本批量生成地址列表。
- 变体：字段是浮点/Unicode/字节时，遍历时要切换值类型与显示格式（人物名常为 Unicode，坐标常为 float）。
- 变体：64 位游戏寄存器与调用约定不同（`rcx/rdx/r8/r9`、栈参数偏移不同），但“固定前缀 + 枚举末级偏移 + 访问断点回溯”的思路不变。
- 关联：[[code-analysis-reverse-windows-game-list-data-pointer-chain]]（列表类数据的 CE 值扫描 + 堆栈回溯，覆盖卡在 `[esp+xx]` 时的三种解法）。
- 关联：[[code-analysis-reverse-windows-game-control-pointer-chain]]（UI 控件的小对象回溯大对象指针链，同样涉及结构体偏移枚举）。
- 关联：[[code-analysis-reverse-windows-game-call-send-backtrace]]（从 send 断点回溯功能 call，堆栈回溯的另一应用）。
- 边界：偏移随游戏版本/角色类型变化；反调试、结构体加密、字段与服务端不同步时，遍历和静态偏移都会失效。

## 检测与防御

- 这是逆向/游戏数据分析技术，不是服务端漏洞；防御方（游戏/客户端）可采取：
  - 服务端权威：血量、蓝量、ID、坐标等关键属性以服务端为准，客户端只做展示；对异常数值做校验。
  - 结构体混淆：字段加密/异或、指针混淆、随机化结构布局与偏移，增加遍历与偏移复用的成本。
  - 反调试/反作弊：检测 CE/x32dbg 附加、硬件断点、调试寄存器、可疑读写；对内存扫描行为做风控。
  - 完整性校验：校验关键字段与结构体布局，检测运行时篡改。
- 检测思路：同一进程对角色结构附近大量偏移的连续读取；调试器附加；当前值/最大值被同时改写；客户端上报数值与服务端模拟不一致。
