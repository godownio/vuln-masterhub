## 一句话结论

对一条「非常规访问流程」的告警 IP，先用威胁情报判恶意、用空间测绘看它上面挂了什么站，再**反查该 IP 解析的域名**，然后走三条互相独立的公开数据路径确认归属——ICP 备案查询（主体实名）、云厂商账号找回页（回显账号/手机号前缀）、WHOIS 注册人信息——三路结论一致时才能把「这台云主机」归到某个实名主体；单一路径（尤其只有一个域名做过备案）不足以定人，因为主机可能早已被控成跳板。

## 原理

- **中国境内云主机 + 域名必须备案**：在国内云上运行网站，域名需完成 ICP 备案，备案信息（主体名称/证件类型/备案号/审核时间）可公开查询。因此「IP → 该 IP 上解析的域名 → 备案主体」是一条合法的公开数据链，能把匿名 IP 关联到实名主体。
- **域名反查是枢纽**：空间测绘（FOFA/微步等）能列出该 IP 上搭建的站点与端口；威胁情报能给出反查域名列表与历史解析。一个 IP 往往解析多个域名，其中只要有一个走过备案，就有归属线索；多个域名还能互相印证是否同一主体。
- **云账号找回页是独立旁证**：云厂商的「找回账号/忘记密码」流程在输入域名或站点信息后，会回显账号的部分信息（如账号名、绑定手机号前缀）。这不涉及登录或越权，只利用公开的找回流程做「该域名确实挂在某个云账号下」的确认，与备案信息比对可提高置信度。
- **WHOIS 注册人是第三路**：域名 WHOIS 的注册人/注册邮箱/注册时间与备案主体、找回页信息比对；国内域名注册信息往往与备案主体一致，国际域名可能开了隐私保护则无此路。
- **为什么必须交叉验证**：单看备案只能证明「有人用这个域名备过案」，不能证明「攻击者是这个人」；单看 WHOIS 可能是代注册/隐私保护；单看情报只能说明 IP 有恶意历史（可能是被入侵的肉鸡）。三路一致 + 时间线（备案时间与域名注册时间接近、站点在该 IP 上长期存在）才构成可用结论。
- **结论边界**：即使归属确认，也只能得出「该主机/域名归属于某主体」，不能直接认定「该主体实施了攻击」——原文最终也推测该云主机可能已被劫持为跳板。进一步的人肉（社工库查手机号关联账号等）属违法且不可验证，不在可复用范围内。

## 触发条件

- 已有明确告警并确认是真实攻击流量（不是扫描误报），拿到攻击源 IP。
- 该 IP 为国内云主机（阿里云/腾讯云等）并承载了可访问的 Web 服务，且有域名解析到它。
- 需要在授权范围内做溯源（护网/应急响应授权），只使用公开数据源。
- 具备威胁情报、空间测绘、ICP 备案查询、WHOIS 查询等公开工具的访问条件。

## 利用步骤

1. 固定证据：从全流量/探针告警里导出攻击 IP、时间、请求特征，确认是「非常规访问流程」而非误报，先做封禁处置。
2. 判恶意与画像：用威胁情报平台查该 IP 的标签（恶意 IP、历史攻击类型、关联样本），记录情报结论作为第一层依据。
3. 看它挂了什么：用空间测绘查该 IP 开放的端口与站点标题/指纹（常见是游戏站、仓库管理系统、管理后台），判断是否有可直接利用的面（多数没有实际价值，此路走不通就转归属分析）。
4. 反查域名：用情报平台的「反查域名」功能列出解析到该 IP 的域名；逐个访问确认站点存活、是否显示备案号。
5. **路径一 ICP 备案**：拿域名到工信部备案查询/第三方备案查询查主体名称、备案号、审核时间；国内云 + 已备案 ⇒ 主体为实名信息。
6. **路径二 云账号找回**：在该云厂商的「找回账号/忘记密码」页输入域名或站点相关信息，观察回显的账号名/手机号前缀，确认该域名归属某个云账号，与备案主体比对。
7. **路径三 WHOIS**：查域名注册人、注册邮箱、注册/到期时间，与备案主体和找回页信息比对；注册时间与备案时间接近可作为加分项。
8. 汇总结论：三路一致 → 输出「IP/域名 → 实名主体」的归属结论，并标注证据等级与不确定性（是否可能为跳板、备案是否可能为代备案）。
9. 处置：封禁 IP 与域名、上报协查；如需进一步身份核实，走法务/公安渠道，不要自行使用非法社工库。

## 变体与关联

- **无域名只开端口**：只能走情报 + 指纹 + 证书（TLS 证书 SAN/CN 常含域名）反查；证书透明度日志可补出域名，再接备案路径。
- **CDN/代理前置**：解析到 CDN 时反查到的是 CDN 节点，需从证书、源站特征或历史解析找真实源站 IP。
- **境外主机**：无 ICP 备案可查，改走 WHOIS、ASN 归属、证书、公开注册信息；归属到自然人的难度显著上升。
- **多域名同主体**：多个域名备案主体相同、且都解析到同一 IP，可作为「同一运营者」的强证据。
- 关联：[[defense-incident-response-supply-chain-phishing-fake-login-attribution]]（同属「域名/备案/历史资产」多源归因，那条是钓鱼站溯源）、[[pentest-recon-equity-icp-subsidiary-domain-asset-discovery]]（备案反查资产的正向用法）、[[pentest-recon-whois-registrant-email-reverse-ip-pivot]]（WHOIS 注册人 + 同 IP 反查）、[[defense-incident-response-public-evidence-source-audit-cross-validation]]（证据分级与结论边界的通用方法）。

## 检测与防御

- 防守方法论：溯源结论必须写清「每条证据来自哪个公开数据源、置信度如何、是否可能被伪造（代备案/隐私保护/跳板）」，避免把归属结论直接写成「攻击者=该人」。
- 处置优先级：先封禁与止损，再做归属；归属用于协查与复盘，不影响阻断决策。
- 反溯源对抗（攻击者视角的防御提示）：不要用实名备案域名承载攻击基础设施、不要在同一云账号下混合正常业务与攻击资产、不要把管理后台暴露在公网。
- 合规红线：只使用公开可查数据；社工库、身份库、购买个人信息等手段属违法，不应纳入任何处置流程。
