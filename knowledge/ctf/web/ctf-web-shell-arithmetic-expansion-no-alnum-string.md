## 一句话结论

题目的正则把字母与数字全部拦掉、只留下 `$ ( ) - . ~` 这类符号，且目标变量的值最终被拼进命令/文件名里。由于 shell 会先做命令替换与算术展开再做拼词，攻击者可以用空 `$()` 取到 0、用 `$((~$(())))` 取到 `-1`，再把若干个 `-1` 直接相邻写成 `-1-1-…` 让算术展开求值，从而「不写任何字母数字」就拼出所需的十进制数字串；把内层写成 13 段 `$((~$(())))`（合计 `-13`）再在外层套一次 `~`，即按二进制补码语义得到 `12`，命中目标 `12.php` 这类文件名，完成绕过。

## 原理

- **展开先于过滤后的使用**：过滤发生在应用层对输入字符串做正则匹配时，而 shell 解析发生在变量被插入命令（`system("... $x ...")`、写文件、`include` 等）之后。输入里字面上只有符号，正则通过；shell 一旦解释，`$()`/`$(( ))` 会把符号「求值」成内容，等于在过滤之后凭空生成字母数字。
- **`$()` 是空命令替换**：`$()` 执行一个空命令，标准输出为空串；在算术上下文里空串被当作 0，于是 `$(())` = `0`、`$(()` 这种空替换在字符串上下文里不产生字符，可用来「生成一个 0 而不写数字」。
- **`~` 是按位取反**：`$((~0))` = `-1`。这提供了「不写任何数字就得到值 1 的载体」——虽然结果是 `-1`，但它的十进制文本里带着字符 `1`。
- **相邻负数直接拼接即隐式求和**：算术展开内部 `-1-1-1` 不需要空格或运算符之外的字符，n 个 `-1` 相邻就是 `-n`；再外套一层 `~`，按二进制补码 `~(-n) = n-1`，因此「13 个 `-1` + 外层 `~`」正好得到 `12`。原文 payload 就是这个「外层取反 + 内层 13 段 `$((~$(())))`」的组合，一个表达式产出目标数字 `12`（配合程序自身拼的 `.php` 后缀构成 `12.php`）。
- **为什么用「重复段数」而不是单个数**：目标是一个文件名（原文为 `12.php`），其中数字部分 `12` 需要由纯符号产出；算术展开只能给出数字，所以利用点在于「用段数凑出数值」，字母部分（`.php`）则由目标程序自身的字面量拼接，原文即以 `$x=12.php` 的判定条件为靶。

## 触发条件

- 输入经过「只允许某些符号、禁止 `[a-zA-Z0-9]`」的正则校验，且校验结果被放进会被 shell 二次解释的位置（命令拼接、文件名、`include` 参数等）；
- 该位置所处的解释器中 `$()`、`$(( ))`、`~` 可用（POSIX shell/bash 均可，sh 亦支持算术展开）；
- 目标文件名/命令片段只由数字与程序自定义的固定字面量构成（否则纯算术无法产生字母）。

## 利用步骤

1. 审计过滤正则，确认被禁字符集只覆盖字母与数字，`$ ( ) ~ - .` 等符号可用。
2. 确认变量最终流向：是被 `system`/`exec` 拼接、被当成文件名写入、还是被 `include`；只有「会被 shell 解释」的位置才能触发算术展开。
3. 先用最短表达式验证展开：提交 `$((~$(())))`，若目标把结果显示/报错回显，应看到 `-1`，即证明符号可穿透到 shell。
4. 按目标数值构造：用 n 段 `$((~$(())))` 相邻得到 `-n`，外层再套 `$((~ … ))` 按 `~(-n) = n-1` 得到 `n-1`；要得到 `12` 就写 13 段。
5. 提交该表达式，检查目标变量（原文为 `$x=12.php`）是否被判定相符（进入下一分支/回显 flag）。
6. 若仍不匹配，加减 `$((~$(())))` 段数即可：外层 `~` 下每多一段值加 1（`~( -(n+1) ) = n`），可覆盖所需整数。

## PoC

原文给出的最终 payload（照抄形态，本卡未执行；按 `~(-n) = n-1` 可复算出值为 `12`）：

```
$((~$(($((~$(())))$((~$(())))$((~$(())))$((~$(())))$((~$(())))$((~$(())))$((~$(())))$((~$(())))$((~$(())))$((~$(())))$((~$(())))$((~$(())))$((~$(())))))))
```

结构拆解：最外层 `$(( ~ $(( … )) ))` 做一次按位取反；内层是 13 个 `$((~$(())))` 紧邻拼接（每个为 `-1`，合计 `-13`），`~(-13)` 按二进制补码即 `12`，正好等于目标 `$x` 需要匹配的数字部分（后缀 `.php` 由程序自身拼接）。原文本条 payload 实测通过，但未给出逐层求值过程与完整源码；复现时需注意 `sh` 与 `bash` 对嵌套 `$((` 的解析略有差异。

要点：数值只由内层 `$((~$(())))` 的段数决定（外层 `~` 下段数 n 对应值 n-1）；调整时只增减重复段，不要插入空格或其它运算符（可能被过滤或改变词法）。

## 变体与关联

- **变体（换取反载体）**：`~` 之外还可用 `$(( 0#… ))`、`$(( 16#… ))` 的进制前缀、或 `${#VAR}` 取长度来产生数字；也可用 `$?`（上一条命令退出码）构造小整数。
- **变体（产生字母）**：纯算术只能给数字，需要字母时通常借助环境变量（`$PATH`/`$HOME` 切片）、通配符展开（`/?in/?at`）、或程序自身已有的字面量；本卡只覆盖原文用到的「数字串」路径。
- **关联**：[[ctf-misc-bash-arithmetic-array-index-sleep-blind]]（同一类「算术展开内嵌命令替换」的 bash 语义利用，入口是数组下标）、[[web-php-rce-no-alnum-self-increment-variable-function]]（PHP 侧用 `++` 自增拼函数名的无字母数字路线）、[[ctf-web-php-double-eval-xor-backtick-command]]（同赛事另一题的 PHP 双重 eval + 反引号命令执行）。

## 检测与防御

- **检测点**：请求参数中出现 `$(`、`$((`、`~$(`、`${#` 等「算术/命令替换」特征串，且参数中**没有**任何字母数字，是最强的异常信号；正常业务参数几乎不会长这样。
- **修复**：不要用「只禁字母数字」的正则做安全边界——它既拦不住符号型 payload，也容易误伤；应改用严格白名单（`^[a-z0-9_]{1,32}$` 这类**正向**校验）、或直接消除「把用户输入拼进命令」的设计（用参数数组/`escapeshellarg`/`proc_open` 传数组）。
- **加固**：命令执行处避免 `sh -c` 拼接；若必须拼接，先做参数化校验再做转义，并对拼接后的字符串再做一次「不含 `$`、反引号、换行」的检查；PHP 侧禁用 `system`/`exec`/`passthru`/反引号，或用 `open_basedir` + `disable_functions` 缩小影响面。
