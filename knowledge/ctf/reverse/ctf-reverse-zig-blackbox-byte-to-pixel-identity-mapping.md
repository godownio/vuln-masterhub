## 一句话结论

当加密器二进制（本例为 Zig 编写）符号清晰但 `main` 因编译期展开大到无法逐行静态分析时，把它当黑盒：构造每个字节取不同值的探针输入喂给程序，若输出图像中每个像素的 `R=G=B` 恰好等于输入字节（如 `0x80→128`），说明“加密”只是把输入文件按字节直写为像素灰度的封装；随后按行优先读取 `secret.enc` 每像素第一通道即可还原明文，JPEG 有损造成的少量坏像素用已知明文/文本冗余纠正。

## 原理

- **黑盒函数探测模型**：把程序视为确定性函数 `Y = F(X)`。选一组覆盖不同位权、彼此可区分的探针字节（如 `0x80 0x40 0x10 0x20 0x01 0x02 0x02 0x04 0x04 0x05`）写入文件交给程序，再观察输出结构。若输出图像的像素值逐项等于输入字节，则 `F` 在字节级别是恒等映射，仅做了“二进制→图像容器”的重排，不存在真正的密码学变换。
- **映射成立的结构原因**：程序把输入文件读成字节数组后，按每字节生成一个像素，三个颜色通道写同一个值（灰度图），像素总数向上取整到输出宽高（本例 4×4=16，输入 10 字节，其余用 `0x3D`（`'='`）填充）；因此密文不是“加密结果”，而是原文的像素化容器，读取方向就是解码方向。
- **为什么优先黑盒**：Zig 的 `comptime`、泛型与标准库被大量内联，`main` 在 IDA 中膨胀成远超屏幕的流程图，循环被 SIMD 向量化（大量 `vmovups ymm` 批量搬运），静态逐指令还原成本极高；而黑盒只需运行数次并读取输出，就能确定输入到输出的映射关系，避开整段逻辑。
- **JPEG 有损的干扰**：本例输出文件头为 `FF D8 FF E0 ... JFIF`，是 JPEG 而非 PNG；JPEG 解码后的像素值会出现 ±1 偏差和个别坏点，导致按像素读回的文本出现字符错误（如 `JPEG` 读成 `IPEG`）。若原文是可预测内容（百科词条、文件魔数、`flag{` 前缀等），可用上下文纠正坏字节，得到完整明文。
- **信息量判断**：恒等映射意味着每个输入字节独立占一个像素、互不扩散；只要输出分辨率与输入长度匹配，就能逐个像素精确还原，不存在分组密码的雪崩效应。

## 触发条件

- CTF 逆向题给出一个可执行加密器加一个待还原的输出文件（常见为图片容器），且程序可重复运行、结果确定（相同输入产生相同输出）。
- 静态分析性价比低：符号虽在，但主函数因编译期展开/内联/向量化而巨大，或算法被 SIMD 批量操作掩盖。
- 输出文件能被常规图像库（PIL/OpenCV）按像素读取，像素值与输入字节存在可观察的简单对应关系。
- 加密器接受文件路径参数，能反复用自制输入调用（本例用法为 `./tetim.elf embed <input>`）。

## 利用步骤

1. **识别输出容器**：先看输出文件头。`FF D8 FF E0` 开头、含 `JFIF` 字样即为 JPEG（有损）；`89 50 4E 47` 为 PNG（无损，优先走精确读取）。注意扩展名可能具有欺骗性。
2. **确认程序用法**：直接运行程序（不带参数）获取回显，本例打印程序名 `TETIM` 与用法 `./tetim embed input`，据此确定子命令与输入参数位置。
3. **构造探针输入**：取若干位权不同、值可区分的字节写成一个二进制文件，用加密器生成输出。
4. **对比输入与输出像素**：用 PIL 打开输出，按 `y` 外层、`x` 内层顺序打印每个像素的 RGB；若像素 `(v,v,v)` 与输入字节一一对应，且输入不足处为固定填充值，则确认逐字节恒等映射。
5. **读取 secret 文件**：对题目给的 `secret.enc` 按同一像素顺序取第一通道（R），拼接成字节串输出。若输出为 JPEG，检查文本/文件头中的坏字节，借助已知明文语境纠正。
6. **按纠错后的字节流识别原文类型**（本例为一段百科文本，其中夹带 `MAPNA{...}` 形式的 flag），完成还原。

## PoC

探针与映射确认（最小化）：

```python
import os
from PIL import Image

with open("a.bin", "wb") as f:
    f.write(b"\x80\x40\x10\x20\x01\x02\x02\x04\x04\x05")
os.system("./tetim.elf embed a.bin")  # 生成 a.bin.enc
img = Image.open("a.bin.enc")
print(img.size)  # (4, 4) -> 16 像素，容纳 10 字节输入 + 6 字节填充
for y in range(img.size[1]):
    for x in range(img.size[0]):
        print(img.getpixel((x, y)))  # 与输入字节逐一相同，尾部为 (61,61,61)=0x3D
```

从 secret 图像还原字节流（最小化）：

```python
from PIL import Image

img = Image.open("secret.enc")
data = b""
for y in range(img.size[1]):
    for x in range(img.size[0]):
        c = img.getpixel((x, y))
        data += bytes([c[0]])  # 灰度图三通道相同，取第一通道即可
print(data)
```

若输出为 JPEG，`data` 中可能有少量字节偏差，用文本上下文/已知文件头人工或脚本纠错；无损 PNG 则无需此步。

## 变体与关联

- **无损 vs 有损**：PNG 输出可逐字节精确还原；JPEG 输出必须处理量化误差与坏点，可靠性取决于原文冗余度。若题目要求精确 flag，可对候选坏点做上下文匹配或利用 flag 格式约束求解。
- **非恒等映射的推广**：若像素值不是输入字节本身，可做差分探针——只改变输入的一个字节，观察哪些输出像素变化、如何变化，从而判断是 XOR/加法/查表等简单映射；逐字节独立时仍可直接反解。
- **通道选择**：数据可能藏在 R/G/B 某一通道或三通道同值；先打印完整 RGB 再判断。像素顺序也可能按列优先或按块重排，需要先用小尺寸探针确定遍历顺序。
- **关联卡**：`ctf-reverse-gdb-blackbox-bytewise-plaintext-brute` 用 gdb 断点做逐字节黑盒比对；`ctf-misc-xlsx-chosen-plaintext-blackbox-function-recovery` 用选择输入拟合黑盒函数；本卡是“探测发现字段直映射到输出像素”的更直接形态。图像数据提取侧可参考 `ctf-misc-rawpy-arw-raw-image-visible-lsb`（像素级读取思路，但那是 LSB）。

## 检测与防御

- 出题/设计侧：不要把敏感字节直接写入像素值再交有损格式，否则几乎等于明文；至少应做逐字节加密（XOR/流密码）并验证字节独立性与扩散性，或输出有损格式以外再加扰动。
- 防守/取证侧：遇到“二进制+图片输出”的可疑程序，按文件头判断容器类型，检查像素是否直接承载明文/密钥；对 JPEG 坏点用已知明文纠错后仍可提取。
- 分析侧：黑盒探测前确保程序无联网、无破坏性副作用；探针输入应短小且可区分，先在小尺寸上确定遍历顺序与填充规则，再读大题输出。
