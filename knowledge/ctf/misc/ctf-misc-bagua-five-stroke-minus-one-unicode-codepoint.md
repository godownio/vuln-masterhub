## 一句话结论

密文按每五个汉字一组、共 72 组排列时，不要把每个字单独映射成八卦；正确粒度是“一组五个字 = 一个符号”：每字笔画数减一得到 0–9 的数字，五个数字按序拼成一个 Unicode 十进制码点，解出八个卦名（震、艮、巽、离、乾等），再把每个卦按三爻转成 3 位、三卦拼成 9 位并补零成 8 位 ASCII，得到 24 字符明文。

## 原理

- **错误直觉**：每组五个字、八卦八种，最容易想到“每字笔画对八卦、五卦十五位”。但笔画范围 1–11 压缩到 8 种需要额外规则，题面没给；15 位不是字节整数倍；360 个字若每字一位，信息量远超最终 24 字符（192 位）。
- **正确粒度**：把每组五个笔画数当成一个五元组，统计 72 组共有多少种不同元组——恰好 8 种，这才是“八卦”的含义。一个五元组对应一个卦名。
- **笔画减一拼码点**：每个字取笔画数减一（1→0、2→1、…、10→9），得到五个 0–9 数字，按顺序拼成十进制数，即一个 Unicode 码点。例：卅玲吹吩天笔画 4,9,7,7,4 → 3,8,6,6,3 → 38663 → U+9707 震。
- **为什么八个卦名能被稳定编码**：八个卦名的码点首位是 2 或 3（如震 U+9707、艮 U+826E、巽 U+5DFD、离 U+79BB、乾 U+4E7E），减一后落在 1–3 的笔画范围内，所以这八个字本身能被笔画减一稳定还原。
- **笔画数据源**：用 Unihan 的 `kTotalStrokes` 字段，位于 `Unihan_IRGSources.txt`；找错到 `DictionaryLikeData.txt` 会 grep 出零条。
- **卦转二进制**：每个卦取三爻，自上而下阳爻=1、阴爻=0；三卦九位，最高位补零成八位即一个 ASCII 字符；72 组 / 3 = 24 字符，正好是 flag 长度。

## 触发条件

- 密文由固定长度的汉字组（本题每组 5 字）组成，组数能被 3 整除。
- 题面提示“八卦/卦象/笔画”等关键词，且文字笔画数据可查（Unihan kTotalStrokes）。
- 五元组种类数恰好为 8，或解出的码点落在常用汉字/符号区间。
- 最终字节流可打印（flag 格式）。

## 利用步骤

1. 按空格切分得到 72 组、每组 5 字；统计每组的笔画五元组种类，确认只有 8 种。
2. 查 Unihan `kTotalStrokes` 得到每个字的笔画数；若使用其他字典，先做小样本对账。
3. 每字笔画减一，五个数字按序拼接为十进制码点，`chr(int(s))` 得到卦名。
4. 对 72 个卦名用三爻表转 3 位二进制：乾 111、兑 011、离 101、震 001、巽 110、坎 010、艮 100、坤 000。
5. 每三个卦拼成 9 位，补前导零成 8 位，转 ASCII，得到 24 字符明文。
6. 对异常组做笔画标准修正：Unihan 用传统/日韩笔顺，与现代简体有出入；本题 `及` 按四画、`做` 按七画修正后，第 30/31/45 组全部归位。若修正方法正确，应能同时解决多个独立异常组，这本身是交叉验证。

## PoC

```python
BITS = {
    "乾": "111", "兑": "011", "离": "101", "震": "001",
    "巽": "110", "坎": "010", "艮": "100", "坤": "000",
}

# 1) 五字组 -> 笔画减一 -> Unicode 码点 -> 卦名
codepoint = int("".join(str(strokes(ch) - 1) for ch in group))
gua = chr(codepoint)

# 2) 三卦 -> 9 位 -> 8 位 ASCII
out = ""
for k in range(0, len(seq), 3):
    bits = "".join(BITS[g] for g in seq[k:k+3])
    out += chr(int(bits, 2))
```

## 变体与关联

- **编码变体**：五笔/四角号码/仓颉等字形编码；只要“每组字 -> 数字/码点”的映射可逆，就能套用同样的分组统计方法。
- **笔画标准差异**：Unihan `kTotalStrokes` 与简体规范不一致会导致个别字偏差；用多个异常组同时修正成功来验证修法。
- **卦序变体**：先天/后天八卦、爻序自下而上/自上而下会改变位序，需要先用已知前缀（如 `flag{`）对账。
- **关联**：与“中文编码套娃”“Unicode 隐写”同类；本卡强调先做元组种类统计再定粒度。

## 检测与防御

- 解题侧：先统计分组元组种类，确认编码粒度；再用已知明文前缀验证卦序与位序。
- 防护侧：这类字形编码不是加密，只是隐写/混淆；敏感数据应使用标准加密而非自定义编码。
- 检测特征：固定长度汉字组、五元组种类为 8、笔画减一后码点落在汉字区、三卦九位补零成 ASCII。
