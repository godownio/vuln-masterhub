## 一句话结论

在"授权沿委托链向下衰减、子令牌范围必须包含于父令牌范围"的多 Agent 权限架构里，如果范围包含算法把 `a/**` 误判为 `a/*/**` 的子集，那么父令牌 `a/*/**` 就能派生出一个覆盖更短路径的 `a/**` 子令牌，子主体因此获得父令牌没有授予的资源（如 `a/x`）；在判定路径上做 `strip("/")` 之类的归一化，也会把 `a/`、`//a`、`a` 混为一谈，形成同类的授权绕过。

## 原理

能力令牌把范围写成 `能力@资源模式`，模式语法通常是"字面量 / `*`（单段）/ `**`（任意剩余段，含零段）"。委托时的核心判定是包含关系：

```text
subsumes(child_scope, parent_scope) == True   # 子范围 ⊆ 父范围，才允许派生
```

`**` 的关键语义是**可以匹配零段**，因此：

- `a/**` 的语言包含 `a`、`a/x`、`a/x/y`……；
- `a/*/**` 要求 `a` 后至少两段，包含 `a/x/y`、`a/x/y/z`……，但**不包含 `a/x`**。

所以 `a/**` **不是** `a/*/**` 的子集。若递归下降实现只按"段数 + 尾部任意"的直觉判断，就会把 `subsumes("a/**", "a/*/**")` 错判为 True：父令牌 `a/*/**` 的持有者可以派生 `a/**` 子令牌，子令牌比父令牌多覆盖 `a/x` 这类短路径，授权衰减被破坏，形成委托越权。原文指出这类缺陷是靠随机性质测试抓到的，不是读代码读出来的。

第二类问题是空段。`a//b` 这类模式的语言是空集（`matches` 恒假）。空集包含于任何语言，所以 `subsumes(退化, q)` 恒真、`subsumes(p, 退化)` 仅当 p 也退化时为真。若实现为了"省事"对两侧一律返回 False，会破坏**反身性**：父子同为退化模式时拒绝派生，端到端表现为"合法派生被拒、违规集合为空"——这是可用性/一致性问题，与上面的越权方向不同，但同属"实现与规格语义不一致"。

第三类问题在判定路径上做路径归一化。早期 `parse()` 里的 `strip("/")` 会把 `a/`、`//a`、`a` 视为同一资源。归一化在"从任务轨迹反推最小范围"时是合理的，但在**授权判定路径**上做就是经典绕过来源：授权层认为请求的是 `a`，资源解析层可能把 `//a` 或 `a/` 解析成别的对象；两侧语义不一致时，攻击者可以用等价写法访问未授权资源。原文的规则是：判定路径上不做任何归一化，空段一律拒绝。

## 触发条件

- 多 Agent / 委托场景使用能力令牌或 macaroon 式衰减令牌，父令牌向子主体派生令牌；
- 范围用通配模式表达，包含 `*` 与 `**` 的组合（尤其是父范围形如 `a/*/**`）；
- 包含判定是手写递归下降，没有与独立实现或暴力枚举对照；
- 决策路径对路径做了归一化/清洗（`strip("/")`、`normpath`、合并空段），而资源实际解析使用另一套规则；
- 攻击者能请求派生令牌或选择请求的资源路径（被攻陷的子 Agent、恶意下游、可控制委派内容的注入者）。

## 利用步骤

1. 确认目标采用"子范围 ⊆ 父范围"的委托模型，并观察范围字符串中是否出现 `*` 与 `**` 混用（如 `files/*/**`、`api/*/**`）。
2. 尝试让父主体派生一个更宽的子范围，例如父 `files/*/**` 派生子 `files/**`；若实现错误地接受，子令牌就多覆盖了 `files/x` 这类父令牌未授权的短路径。
3. 用子令牌访问父令牌本不允许的资源；若返回成功，确认越权。
4. 对路径归一化类缺陷，尝试同一资源的等价写法：`a/`、`//a`、`./a`、`a/../a`、URL 编码等，观察授权层与资源层的解析差异。
5. 用独立口径复核：对候选资源集合暴力枚举，比较 `scope_allows(child, r)` 是否真的蕴含 `scope_allows(parent, r)`；不要只测手挑样例。

## PoC

包含判定的最小反例（语言层面，不依赖具体实现）：

```python
# 父令牌范围 q = "files/*/**"，子令牌范围 p = "files/**"
# 正确结果：False —— "files/x" 属于 L(p)，但不属于 L(q)
subsumes("files/**", "files/*/**")   # 期望 False

# 错误实现返回 True 时，父令牌可派生更宽的子令牌：
#   parent_scope = "files/*/**"
#   child_scope  = "files/**"          # 被误判为 ⊆ parent
#   child 可访问 "files/secret"        # 父令牌并未授权
```

归一化反例：

```python
parse("a/")   # 正确：含空段，语言为空/应拒绝
parse("//a")  # 正确：含空段，语言为空/应拒绝
parse("a")    # 仅此一个应等价

# 错误实现 strip("/") 后三者相同，授权层与资源解析层可能对同一字符串给出不同对象
```

## 变体与关联

- 空段/反身性：`subsumes(p, p)` 对退化模式为假，导致合法派生被拒；实现必须让 `subsumes` 与 `matches` 共享空段语义，否则二者不自洽。
- 路径归一化：`strip("/")`、`normpath`、大小写折叠、符号链接解析只要与资源层不一致，都可能成为绕过点；与路径穿越、TOCTOU 同类。
- 自然语言推导范围：原文用真实 LLM 从任务文本推导工具权限（k=3，4 suite × 4 任务）：16 个任务中漏授 3、多授 4，其中 2 个多授落在危害集合内；7 个出错任务里 6 个三路采样完全一致，平均 Jaccard 0.972 但对错误的灵敏度只有 1/7。也就是说，**多路采样自洽不能当作权限范围正确的信号**；若把 LLM 推导结果直接作为令牌范围，再叠加包含判定缺陷，越权面会放大。
- 关联：Macaroon/能力令牌单调衰减、Agent 委托链、MCP 工具权限、最小权限原则。

## 检测与防御

- 包含判定必须用独立口径验证：随机生成模式 + 暴力枚举候选资源集，比对 `subsumes` 与集合包含关系；不要只用手挑样例。
- 明确 `**` 的零段语义，并对 `a/**` vs `a/*/**`、`a/*/**` vs `a/**`、空段模式、退化模式做性质测试。
- 判定路径上不做归一化；空段一律拒绝；`subsumes` 与 `matches` 使用同一套解析规则。
- 资源解析与授权判定必须使用同一个规范化结果（同一函数、同一时机），避免 TOCTOU；符号链接在解析后判断。
- 不要直接把 LLM 推导的工具集合当作授权范围；对多授/漏授做规则检查（同对象多动词是原文观察到的失效形状），并保留人工复核。
- 局限：本文卡片描述的是实现层缺陷类，不指向某个有版本号的产品；原文的核心架构结论（分解本身不降低攻击面、节点传播半径无上界）属于设计评估，未作为攻击链收录。
