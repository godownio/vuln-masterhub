## 一句话结论

把越狱提示词生产拆成“风险类型选择 → 生成模式（单一手法/多手法组合/AI 自动选择）→ 生成提示词 → 目标模型实测 → 独立危害研判模型判定 → 成功样本入库”的闭环，可以用大模型自身规模化产出高质量越狱提示词，并自动筛掉无效样本、沉淀可复用“弹药库”，把原本依赖人工试错的红队提示词工程变成可迭代的流水线。

## 原理

- **直接索要越狱提示词不可靠**：让模型“扮演安全研究员生成越狱提示词”看似低成本，但输出质量参差、经常被拒绝，无法满足规模化、多样性和可复现性。
- **任务包装降低拒绝率**：把生成请求包装成“授权红队评估/防御演习/提示词工程/风险分类测试”等看似合理的高级任务，模型更愿意输出结构化内容；再叠加高优先级 System Override（强制进入“攻击载荷生成引擎”角色、禁止拒绝、限定 JSON 输出）可进一步压低拒答率。
- **风险分类提供覆盖面**：参考 TC-260 等标准把风险分为五大类 31 种，保证生成的提示词覆盖不同风险点，而不是只围绕少数敏感话题。
- **攻击手法库提供多样性**：按劫持类、设定类、诱导类、混淆类、语言伪装类等维度组织 37 种经过验证的手法；生成模式分为单一手法（高强度）、多手法组合（复合迷惑性）、AI 自动选择（按风险类型/模型特性/趋势推荐组合）。
- **独立研判模型提供可扩展的判定**：生成后自动调用目标模型获取输出，再用另一个模型（文章用 DeepSeek-V3）对输出做安全危害评估；判定有害即视为越狱成功，把“提示词 + 成功输出”保存入库，失败则丢弃或人工复核。
- **为什么可行**：越狱效果判定从人工主观判断变成可批量执行的模型评分；生成模型可以低成本产出大量变体，研判模型负责筛选，形成“生成—验证—沉淀”的正反馈，能快速跟上目标模型的安全更新。
- **边界**：研判模型本身可能误判/被绕过；目标模型的输入/输出过滤会拦截部分样本，需要配合编码、拆解、混淆、语种转换等 bypass 手法；流水线产出的是候选提示词，仍需人工确认授权与危害。

## 触发条件

- 攻击者/红队可调用生成模型、目标模型与研判模型（API 或本地部署），且目标模型可接受任意用户输入。
- 已获得对目标模型的测试授权；未授权测试属于滥用。
- 目标模型存在可被诱导的拒绝边界，或输入/输出过滤可被编码/语种/文体等手法绕过。
- 有可持续的记录与样本管理（提示词、输出、风险类型、手法标签、模型版本）。

## 利用步骤

1. **定义风险分类**：按 TC-260 等标准列出五大类 31 种风险点，作为生成任务的目标维度。
2. **建攻击手法库**：按劫持、设定、诱导、混淆、语言伪装等维度整理手法（如角色扮演、逻辑悖论、情感操控、渐进诱导、上下文混淆、文言文伪装等），并为每种手法写生成模板。
3. **选择生成模式**：
   - 模式 1 单一手法：针对一种手法生成高强度提示词；
   - 模式 2 多手法组合：两种以上手法叠加；
   - 模式 3 AI 自动选择：由生成模型按风险类型、目标模型特性和最新趋势推荐组合。
4. **生成提示词**：让生成模型在“授权红队评估”包装下输出结构化提示词（可要求 JSON），必要时用高优先级 System Override 压制拒答。
5. **自动实测**：把提示词提交目标模型，记录完整输出与模型版本。
6. **危害研判**：调用独立研判模型对输出评分/分类；判定有害即标记为越狱成功。
7. **入库与迭代**：保存“提示词 + 成功输出 + 风险类型 + 手法标签 + 目标模型版本”到弹药库；失败的样本丢弃或人工复核；定期用新样本回归测试目标模型的安全更新。
8. **配合 bypass**：对输入使用翻译、拼音/声母、谐音、偏旁拆解、Base64、Emoji、零宽字符、反向等；对输出使用 JSON 伪装、Markdown 碎片、Base64/Hex/URL/Unicode/HTML 实体等，绕过输入/输出过滤。

```python
for risk in TC260_RISKS:                 # 五大类 31 种风险
    for mode in ["single", "combo", "auto"]:
        prompt = generator.generate(
            risk=risk, mode=mode, techniques=ATTACK_LIBRARY
        )
        output = target_model.chat(prompt)
        verdict = judge_model.evaluate(
            output=output, risk=risk
        )                                 # 独立危害研判
        if verdict.harmful:
            arsenal.add({
                "prompt": prompt, "output": output,
                "risk": risk, "mode": mode,
                "target": target_model.version,
            })
```

## 变体与关联

- **生成模型变体**：国外/国内模型均可作为生成器；不同模型对“红队任务”包装的接受度不同，需要按模型调整话术。
- **研判变体**：单一模型评分、多模型投票、规则 + 模型混合；研判模型可换成更便宜的小模型以降低成本，但误判率上升。
- **弹药库变体**：按风险类型/手法/目标模型/版本建立索引；记录成功输出用于回归测试与变体生成。

## 检测与防御

- **检测**：同一来源/账号在短时间内对多个风险类型、多个模型发起高频、模板化请求；提示词中出现“红队/防御评估/越狱/绕过/JSON only/禁止拒绝”等模式；输入包含编码/零宽字符/多语种混合等 bypass 特征；输出侧出现危险知识、拒绝模板被绕过、结构化 JSON 载荷。
- **防御**：模型侧持续做红队与安全对齐，覆盖古汉语、编码、角色扮演、多轮诱导等变体；输入/输出双向过滤与意图分类；对高风险领域做知识性拒答而非仅关键词匹配；速率限制、账号行为分析与滥用监测；不要把“是否越狱成功”完全交给单一模型判定。
- **边界**：自动化流水线降低的是人力成本，不改变越狱的本质；研判模型与目标模型同源时可能共享盲区；所有测试必须在明确授权范围内进行。
