## 一句话结论

登录页的「忘记密码」几乎总是账号枚举 oracle（手机号不存在时提示「手机号无效」，存在时提示「验证码已发送」）；用它把按地区号段批量生成的手机号字典筛成有效账号列表，再对每个账号只试「按历史泄露频率排序的头部弱口令」——本例在连续错误 5 次锁号之前就命中，全程不需要任何 0day。

## 原理

- **找回密码必须查库，所以必然可枚举**：接口要决定「发不发验证码」，就得先判断账号是否存在。只要两种结果的文案/状态码/响应长度/耗时不同，就是可用的枚举 oracle；即使文案统一，也常能从响应长度或耗时差分出来。
- **账号是手机号时字典可工业化生成**：手机号 = 地区码 + 号段 + 尾号，号段公开、尾号空间固定，用脚本按目标地区的号段批量产出候选即可。相比盲猜用户名，这种「结构化账号空间」让枚举成本极低。
- **锁号阈值决定爆破策略，而不是阻止爆破**：本例连续错 5 次锁一段时间。正确打法是：①单账号最多试 `阈值-1` 次；②字典按命中概率降序排列（历史泄露高频口令放最前）；③跨账号摊开，避免同一账号连续失败触发锁定；④必要时做「口令喷洒」（一个口令打所有账号），把「一次命中率」换成「规避单账号计数」。
- **弱口令命中率远高于随机**：大量系统仍存在 `123456`、`账号后六位`、`Aa123456`、`admin@123` 一类口令；把最高频的一小撮单独成表，能在极少的尝试次数内覆盖可观比例的账号，正好适配严格锁号场景。
- **为什么这一环最值钱**：它把「只知道手机号」变成「拥有合法会话」，是后续所有越权（水平/垂直）的前置条件；原文也点明整条链里最难的是字典构造与优化，而不是漏洞本身。

## 触发条件

- 登录/找回密码/短信登录接口对「账号是否存在」返回可区分信息（文案、码值、长度或耗时）。
- 账号体系以手机号/邮箱/工号等结构化标识作为用户名。
- 无验证码或验证码可被 OCR/打码绕过；限流只按单账号计数（有锁定阈值但可跨账号规避）。
- 目标用户群体存在弱口令习惯（初始口令、手机号后六位、生日、常见组合）。

## 利用步骤

1. 抓 `forgot password` 请求，提交一个已确认存在的号码与一个随机号码，比对响应文案/状态码/长度/耗时，确认可枚举。
2. 按目标地区生成手机号字典（区号 + 有效号段 + 尾号），控制并发跑枚举，保留返回「已发送/账号存在」的号码。
3. 整理弱口令字典：把历史泄露的高频口令按频率降序，前面放 `123456`、`手机号后六位`、`姓名拼音+生日`、`Aa123456` 等，构造一小份高命中率头部。
4. 对每个有效账号只尝试头部若干条（小于锁定阈值，例如阈值 5 就试 4 条），失败即换下一个账号；全部跑完一轮后再考虑时间窗口允许时重试。
5. 命中后立即登录验证，并检查该账号的权限范围（是否管理员/多身份），决定下一步。
6. 全程记录命中账号与口令，避免重复尝试触发锁定；控制请求速率，不要把测试打成拒绝服务。

枚举差分：

```text
POST /api/forgot/sendCode HTTP/1.1
Content-Type: application/json

{"mobile":"13800000000"}   -> {"msg":"验证码已发送"}    // 存在
{"mobile":"13800009999"}   -> {"msg":"手机号无效"}      // 不存在
```

```python
LOCK = 5                                   # 连续错误 5 次锁定
HEAD = ["123456", "手机号后六位", "Aa123456", "admin@123"]   # 按频率降序，长度 < LOCK

for mobile in enum_ok:
```

## 变体与关联

- 枚举 oracle 变体：注册接口「该手机号已注册」、短信登录「未注册」、头像/昵称占用检测；文案统一时可退化为长度/耗时盲枚举。
- 爆破变体：撞库（跨站口令复用）、口令喷洒（一个口令打全部账号，规避单账号锁定）、默认口令（`admin/admin`）、以及从响应差异判断「账号存在但口令错」。
- 锁定绕过变体：换 IP/代理池绕 IP 级限流；`X-Forwarded-For` 伪造；大小写/空格变体绕「同口令去重计数」；锁定只针对密码不针对短信登录时改走短信通道。
- 关联：与「带图形验证码的账号枚举 + 用户名=口令」互补——那张卡解决验证码，本卡解决锁定阈值与字典排序；与「验证码可预测/可回显」类卡的区别是本卡完全不碰验证码，只在找回密码入口做枚举。
- 关联：与「选择身份 ID 参数越权」常连用——爆破拿到的是普通账号，再靠 IDOR/越权抬到管理员。

## 检测与防御

- 统一响应：无论账号是否存在都返回「如果该账号存在，我们已发送验证码」，并对响应长度、耗时可观测差异做归一化（固定文案 + 异步发送）。
- 全局限流：账号 + IP + 设备指纹三维计数，锁定策略不要只看单账号；对「同 IP 多账号」「同口令多账号」的喷洒特征直接阻断并告警。
- 口令策略：长度下限 + Top 10 万弱口令黑名单 + 禁止与手机号/工号/生日相同 + 首次登录强制改密。
- 加图形/行为验证码到找回密码与登录两条链路（仅加在登录上等于留了枚举口）。
- 检测：监控单 IP 短时间大量 `forgot/sendCode`（枚举特征）、单账号 4~5 次失败（贴近阈值）、以及大量账号用同一口令失败的喷洒特征。
