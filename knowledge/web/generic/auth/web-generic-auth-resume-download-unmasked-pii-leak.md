## 一句话结论

招聘平台在简历详情页对手机号等敏感字段做了掩码展示，但“下载简历”生成的 Word/PDF 文件直接取自完整数据库记录，未做脱敏；任何企业账号下载简历即可拿到学生完整手机号、邮箱、教育经历等 PII，文章进一步用这些手机号接管学生账号。

## 原理

- **两条数据路径不一致**：详情页通常由前端/接口做掩码（如 `13266****`），而下载功能由后端重新查询完整记录并生成文档，掩码逻辑只加在页面渲染层，没有作用到导出/下载路径。
- **下载权限过宽**：企业账号只要能浏览简历，就能下载完整简历；服务端只校验“企业已登录”，没有校验企业与这份简历的投递/招聘关系，也没有做字段级权限控制。
- **文档格式绕过前端限制**：Word/PDF/Excel 由服务端生成，里面的手机号、邮箱、身份证号等字段是完整值；浏览器页面上的掩码、复制限制、水印都不影响文件内容。
- **放大效应**：企业账号通常能看到大量投递简历（文章称每家企业平均约 100 份待就业学生简历），批量下载即可获得大量学生手机号；手机号又可作为短信登录账号标识，与验证码绑定缺陷组合后接管学生账号、读取身份证号并修改密码。

## 触发条件

- 招聘/就业平台存在企业端简历浏览与下载功能。
- 简历详情页对手机号等字段做了掩码，但下载文件未脱敏或使用不同查询。
- 企业账号可访问的简历范围过宽（未按投递关系/招聘职位过滤），或企业账号可被接管/批量注册。
- 下载文件为 Word/PDF/Excel 等可解析格式，包含完整个人信息。

## 利用步骤

1. 以企业账号登录招聘平台，进入“简历管理/人才搜索/收到的简历”等功能，打开一份学生简历。
2. 观察页面展示：手机号、邮箱等是否被掩码（如 `13266****`），记录掩码规则。
3. 点击“下载简历”，抓取下载请求，保存返回的 Word/PDF/Excel 文件。
4. 打开文件，对比页面字段：确认手机号、邮箱、身份证号、教育经历等是否为完整值。
5. 若企业账号权限允许，批量下载/导出简历；统计可获取的学生数量与字段。
6. 将获得的手机号用于学生端短信登录测试（结合验证码绑定缺陷），验证是否能进一步接管学生账号；仅在授权范围内操作。

## PoC

下载请求模板（端点/参数按目标实际调整）：

```http
GET /<recruit-path>/resume/download?id=<resume_id> HTTP/1.1
Host: target.edu.cn
Cookie: <enterprise-session>
Accept: application/octet-stream
```

对比：

- 页面接口返回：`"phone": "13266****"`（掩码）
- 下载文件内容：`手机：13266xxxxxx`（完整号码），并含邮箱、教育经历、求职意向等。

文章实测：企业账号下载简历后，Word 文件中出现完整手机号与个人信息；多份简历均可复现，进而用这些手机号登录学生账号，查看身份证号并修改全部学生密码。

## 变体与关联

- **导出格式变体**：Word、PDF、Excel、HTML、图片简历；批量导出/压缩包下载更容易一次泄露大量数据。
- **脱敏位置变体**：仅前端 JS 掩码、仅列表接口掩码、详情接口掩码但下载不掩码；可用抓包对比各接口返回。
- **权限变体**：企业账号可浏览未投递该企业的学生简历（人才搜索），或通过修改 resumeId 越权下载他人简历。
- **关联**：[[web-generic-auth-sms-login-code-not-bound-phone-parameter-tamper]]（用泄露手机号 + 验证码绕过接管学生账号）、[[web-generic-auth-form-field-id-idor-pii-enumeration]]（批量 PII 越权）、[[web-generic-auth-deepaudit-user-list-missing-role-check-pii-leak]]（用户列表缺角色校验）。

## 检测与防御

- **源头脱敏**：在数据查询/序列化层统一脱敏，页面、接口、下载、导出共用同一套字段策略；下载文件只包含业务必要字段。
- **字段级权限**：企业只能下载与自身投递/招聘关系匹配的简历；对手机号、身份证号等设置字段级访问控制与审计。
- **下载审计**：记录下载人、企业、简历 ID、时间、数量；对短时间批量下载、异常企业账号、跨职位下载告警。
- **水印与追踪**：下载文件加企业标识水印/隐形水印，便于泄露溯源。
- **响应**：确认泄露后限制下载、通知受影响学生、评估是否需重置账号与上报。
