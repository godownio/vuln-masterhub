## 一句话结论

登录成功后很多系统会让用户「选择身份/选择租户/选择组织」再进主页；如果这个选择动作把身份主键（本例是一个明文 `id`，前端变量里就能看到）通过请求参数回传，而服务端只用它去查身份、不校验该身份是否属于当前会话，那么把 `id` 改成别人的值就等于以那个用户身份进入系统，垂直越权（改成管理员）与水平越权（改成任意同事）同时成立。

## 原理

- **两阶段登录把授权决策挪到了第二步**：第一阶段验证口令拿到会话，第二阶段「以哪个身份进入」决定权限上下文。很多实现把第二步做成「前端把选中的 id 提交给后端，后端据此加载身份并写进会话」，于是身份的选择权交给了客户端。
- **前端先泄露了参数名**：原文最初在页面 F12 里就看到一个可疑的明文值，随后在数据包里确认它是 `id`。这说明前端要么把它写在隐藏字段/JS 变量里，要么列表接口直接返回了全部可选身份的 id —— 两者都让攻击者无需猜测参数名与取值格式。
- **缺失的是「归属校验」**：正确实现应校验「请求的 id ∈ 当前会话用户名下的身份集合」，或干脆不接受 id、由服务端从会话里取可选列表并在选择时做成员检查。本例服务端直接按 id 查库并写会话，等同开放了「任意身份代登录」。
- **危害等级取决于身份表**：如果身份表里含管理员账号，这就是完整接管；如果只有普通用户，也构成批量水平越权（可遍历）。因此本类问题通常评为严重。
- **与响应篡改型越权的区别**：那条是靠改响应骗前端（服务端并不认账），本条是服务端真实把会话切成了别人的身份，后续所有请求都以受害者身份执行，危害高一个层级。

## 触发条件

- 登录流程存在「选择身份/租户/组织/角色」的中间步骤。
- 该步骤的请求里携带可枚举的身份主键（`id`、`userId`、`employeeId`、`tenantId`）。
- 服务端按该主键加载身份并写入会话，未校验其与当前登录用户的归属关系。
- 前端把可选身份列表或其主键暴露在页面/JS/列表接口里（大幅降低利用成本，但非必要条件）。

## 利用步骤

1. 正常登录，进入「选择身份」页，先看页面源码与 F12 网络面板：找隐藏字段、JS 变量、以及填充列表的接口响应里出现的 id 类字段。
2. 抓「选择身份」的提交请求，确认参数名与取值（本例 `id` 为明文数字）。
3. 先用自己的 id 提交一次，确认返回的会话/首页数据确实切换到了该身份，建立基线。
4. 把 id 改成相邻值（自增主键可直接 `1`、`2`…）或目标管理员 id，提交；观察返回是否成功、首页显示的姓名/角色是否变化。
5. 用新会话访问仅该身份可见的功能（管理菜单、审批、用户列表），确认越权成立。
6. 若要枚举，写脚本遍历 id 并记录「返回不同用户名/角色」的响应，即可批量列出可接管账号；实战中只做最小验证。

## PoC

```text
POST /api/login/chooseIdentity HTTP/1.1
Content-Type: application/json

{"id":"10086"}          -> 返回自己的身份（基线）
{"id":"1"}              -> 返回管理员身份，会话切换到管理员
```

若参数在 Cookie/表单里，等价写法：

```text
POST /api/login/chooseIdentity HTTP/1.1
Content-Type: application/x-www-form-urlencoded

id=1&_t=1699999999
```

批量探测（只列差异，不做破坏性操作）：

```python
for i in range(1, 200):
    r = s.post("/api/login/chooseIdentity", json={"id": str(i)})
    if r.json().get("username"):
        print(i, r.json()["username"], r.json().get("role"))
```

## 变体与关联

- 参数变体：`roleId`/`tenantId`/`orgId`/`employeeNo`/`openId`；有的放在 JWT payload 或自定义 Header 里，改包即生效。
- 入口变体：除「选择身份」外，还有「切换组织」「切换门店」「切换角色视图」「代登录/代客操作」等所有「以谁的身份行事」的入口。
- 利用变体：id 为自增则直接遍历；为 UUID 时可从列表接口/日志/分享链接里取；为加密串时看能否解密或重放他人值。
- 关联：与「登录响应 resultCode 篡改进入后台」的区别是那条没有真实会话（只骗前端），本条服务端真实切换身份；与「忘记密码枚举 + 弱口令爆破」连用时，先爆破拿普通账号、再用本卡抬到管理员；与「修改密码接口 username 越权」同属「服务端缺失会话归属校验」，但那条改的是口令，本条直接换身份。
- 关联：与「前端硬编码改密入口」「Vue 路由守卫绕过」的区别是那些是纯前端控制，本条是服务端逻辑缺陷。

## 检测与防御

- 身份选择接口不接受客户端传入的身份主键，改为服务端从会话中取「该用户可选身份集合」，客户端只传集合内的序号或 token。
- 必须传 id 时，服务端先校验 `id ∈ 当前会话用户的可选身份集合`，不通过直接 403，并记录审计日志。
- 切换身份签发新的服务端会话/短期凭证，旧的权限上下文立即失效，避免权限上下文串用。
- 前端不要把全部可选身份（含管理员）的主键渲染进页面；列表接口按当前用户权限过滤。
- 检测：同一会话在短时间内提交多个不同 `id` 的选择身份请求；选择身份后紧接访问与该身份权限不符的高危接口；登录后立即出现的 403/200 混合探测序列。
