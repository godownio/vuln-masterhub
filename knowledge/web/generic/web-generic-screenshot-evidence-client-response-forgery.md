## 一句话结论

当退款、销户、学分认定等业务把用户提交的“个人中心/学习进度截图”当作身份、资产或进度凭证，而截图内容完全来自客户端渲染时，攻击者可用代理改响应或在 DevTools 断点改渲染变量，把余额、用户名、学习时长改成任意值再截图提交；配合水平越权挑出高余额目标，即可冒领他人退款或骗客服注销他人账户。

## 原理

- 截图不可信：截图记录的是浏览器渲染结果，渲染数据来自服务端响应与前端 JS 变量，二者都处于用户控制之下——Burp 改响应体、DevTools 下断点改对象、Console 直接赋值都能改变页面显示，而截图无法体现数据来源。
- 信任边界错误：业务流程把“页面上显示的信息”当作“服务端事实”。人工审核只能看到一张图片，无法区分真实页面与改包后的伪造页面，也不会去服务端核对截图中的账户与提交者的归属。
- 前置信息来自越权/泄露：水平越权可批量读取他人 `id`、`nickname`、`balance` 等展示字段，用来挑选高价值目标并填充伪造页面；这与“截图可伪造”叠加构成完整链。
- 流程缺口放大危害：退款只要求截图 + 收款银行卡，销户只要求用户名 + 手机号 + 截图，学分认定只要求学习时长截图；均缺少服务端权威数据核验、账户归属校验与原路退回。
- 之所以成立：客户端渲染层可被完全控制，任何“以截图自证”的人工审核都等价于信任攻击者提交的任意 HTML 渲染结果；业务越依赖截图，越容易被同一手法复用。

## 触发条件

- 业务以用户截图作为资产/身份/进度证明，并依赖人工审核；
- 提交渠道（问卷、客服、扫码上传）不校验提交者与截图账户的归属，也不服务端核对数值；
- 存在信息泄露或水平越权，可获取目标账户的用户名、手机号、余额、学习记录等展示要素；
- 攻击者能用代理工具或浏览器 DevTools 修改前端数据。

## 利用步骤

1. 通过水平越权/信息泄露收集目标账户展示要素（如 `id`、`nickname`、`balance`），筛选高余额或高价值目标。
2. 打开个人中心页面，用 Burp 拦截并修改响应 JSON（如 `balance`），或 DevTools 在渲染函数下断点，修改当前渲染对象。
3. 示例（Console/断点中直接改对象）：
   ```js
   e.nickname = "<目标昵称>";
   e.id = 6247602;
   e.accountInfo.balance = 436;
   ```
4. 恢复渲染，确认页面显示为目标账户信息后截图（必要时带上业务要求的课程名/用户名等元素）。
5. 按业务流程提交截图：退款问卷填写自己的收款账户；销户向客服提供目标用户名与手机号；学分认定上传伪造的学习时长截图。
6. 学分场景可先把学习进度页改为“已完成/满时长”显示再截图，骗过按截图认定学分的流程。

## PoC

无自动化 PoC；核心操作是客户端数据篡改 + 截图：

- 代理方式：Burp 拦截 `GET /ck/user/myInfo` 等接口响应，把 `nickname`、`id`、`accountInfo.balance` 改为目标值，放行后页面即按伪造数据渲染，截图。
- 断点方式：DevTools Sources 在渲染赋值行（如 `var a = {...}`）下断点，手动改写 `e` 对象字段，再放行并截图。
- 若业务要求“截图能看到课程名称/用户名”，同步修改对应字段保持页面自洽。

## 变体与关联

- 变体：学习时长/成绩/签到截图骗学分；个人中心截图骗退款；用户名+手机号+截图骗客服销户；任何“截图自证”的申诉、解封、认证、提现审核。
- 关联：与[[web-generic-client-side-score-trust]]的区别是后者把伪造分数直接提交给服务端接口，本卡不向服务端提交伪造数据，而是伪造给人看；与[[web-generic-payment-amount-tamper-no-order-binding]]同属业务逻辑信任问题；前置的他人余额/资料获取属水平越权（IDOR）。
- 边界：最终能否通过人工审核依赖审核严格程度与业务流程，原文展示了改包截图与越权取数，退款到账/销户成功未完整展示，故 confidence 定为 medium；该手法具有时效性（业务下线即失效）。

## 检测与防御

- 防御：不要把用户截图作为唯一凭证；退款/销户/学分认定应在服务端按账户查询权威数据，并要求账户归属校验（原绑定手机验证码、实名信息、订单/流水号）。
- 防御：退款一律原路退回，禁止退到用户任意填写的银行卡；客服销户走多因素核验，不接收单张截图。
- 防御：截图要求带服务端生成的动态挑战码/水印（时间戳+随机码+账户标识），审核时回查；上传图片做重复检测与拼接/PS 痕迹检测。
- 检测：同一账户短时间多笔退款申请、退款收款账户与账户实名不一致、截图内容与提交账号不匹配、同一图片哈希被多次提交、异常时间集中提交。
