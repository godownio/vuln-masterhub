## 一句话结论

在 32 位游戏中用 CE 对血量做“初值扫描 → 改值再扫”锁定内存地址，再在 x32dbg 对该地址下 4 字节内存访问断点，命中读取血量的 `mov edi,[esi+0x1C]` 后，沿寄存器来源逐层回溯（配合函数头断点 + Ctrl+F9/F8 返层、条件断点识破假来源），最终得到从模块基址到血量字段的完整指针公式，并可用 CE 验证读数与游戏一致。

## 原理

- **CE 搜数**：血量是 4 字节整数。先按当前值（示例 43348）首次扫描，再用道具把血量改成新值（44278）后“再次扫描”，候选会从成千上万缩到少量。以 `00` 开头或成片数值/地址高度相似的候选通常是干扰项。
- **访问断点**：对候选地址下“内存访问、长度 4”的硬件断点（不是写入），让游戏读取血量（扣血/加血/刷新血条），断在读取指令处。示例命中 `mov edi, dword ptr ds:[esi+0x1C]`，`esi=0x45B1A570`，说明血量对象是 `esi`，血量字段偏移 `+0x1C`。
- **逐层回溯**：当前函数内向上找“谁给 `esi`/`ecx` 赋值”；若上方是 `int 3`/无有效赋值，就在函数头部下断，用 `Ctrl+F9`（执行到返回）再 `F8` 单步返回上一层。每层都要用调试器里的寄存器/内存值与游戏真实数据比对，一致才继续。
- **识破假来源**：循环附近常有 `mov ecx,[esp+28]` 这样“看起来像来源”的指令。用条件断点验证：若断下时数据与条件不符，说明实际执行路径不在这里；借助反汇编窗口的跳转来源提示找到真正分支。
- **固定偏移与索引**：`mov ecx,[esi+eax*4+0x320]` 在 `eax=1` 时等价于固定读 `[esi+0x144]`（4+0x320）；`[eax+0x10]` 中被当作索引的量恒为 0x10，也等价于固定偏移。
- **`[ebp+8]` 的语义**：`[ebp+8]` 常是 call 的第一个参数。若 `ebp` 是栈地址，只需返回上一层看调用者传了什么；本例 `ebp` 是堆对象指针，因此继续沿 `ebp` 回溯。
- **终止条件**：当寄存器注释显示其来自模块基址（示例 `xajh.exe+0x11282D8`）时停止，写出“基址+多级偏移”的指针链。

## 触发条件

- 32 位 Windows 游戏客户端，血量等角色数据以“对象+固定偏移”形式存放在用户态内存。
- 能使用 Cheat Engine 附加进程、搜索/修改数值；能使用 x32dbg 附加并下硬件断点。
- 目标未启用阻止调试的强反调试，或已绕过。
- 能通过道具/受伤等操作改变血量，以完成二次扫描与断点触发。

## 利用步骤

1. **CE 首次扫描**：记录当前血量（如 43348），4 字节精确数值扫描。
2. **改值再扫**：使用道具改变血量（如 44278），在结果上再次扫描新值，缩小候选；排除 `00` 开头、成片相似地址。
3. **确认地址**：把候选加入 CE 列表，切到 x32dbg，`Ctrl+G` 跳到该地址，将显示类型改为无符号整型，确认读数与血量一致。
4. **下访问断点**：对该地址下 4 字节内存访问断点，触发游戏读血，命中读取指令，记录对象寄存器与字段偏移（示例 `mov edi,[esi+0x1C]`，`+0x1C`）。
5. **立即取消断点**：避免后续操作反复中断；若游戏卡住，在线程窗口“恢复所有线程”再运行。
6. **逐层回溯**：按“找寄存器赋值 → 若上方是 int3 则函数头下断 → Ctrl+F9 + F8 返层 → 每层核对数据”循环；遇到 `lea ecx,[esi+0x2A0]` 记录 `+0x2A0`，遇到 `mov eax,[esi+0xC8]` 记录 `+0xC8`，遇到 `[eax+0x10]` 记录固定 `+0x10`。
7. **处理循环与索引**：对 `[esi+eax*4+0x320]` 下断观察 `eax`；若为 1 则折算固定 `+0x144`。对可疑的 `[esp+28]` 用条件断点排除。
8. **追到基址**：找到 `mov ecx,[ebx+0x24]` 且 `ebx` 注释为模块基址，记录 `+0x24` 与基址偏移 `0x11282D8`。
9. **写出并验证公式**：按外层到内层串成指针链，填回 CE 读取，应与游戏血量一致。

## PoC

示例公式（地址/偏移仅对该游戏版本有效）：

```text
[[[[[[xajh.exe+0x11282D8]+0x24]+0x8]+4+320]+0xC8]+0x10]+0x2A0+0x1C
```

逐层展开：

```text
P0 = *(xajh.exe + 0x11282D8)   ; EBX，模块基址
P1 = *(P0 + 0x24)
P2 = *(P1 + 0x8)               ; [ebp+8]，call 第一个参数
P3 = *(P2 + 0x144)             ; [esi+eax*4+320]，eax=1 → +0x144
P4 = *(P3 + 0xC8)
P5 = *(P4 + 0x10)              ; 固定偏移 [eax+0x10]
esi = P5 + 0x2A0               ; lea ecx,[esi+0x2A0]
血量 = *(esi + 0x1C)           ; mov edi,[esi+0x1C]
```

关键指令与校验值：

```asm
mov edi, dword ptr ds:[esi+0x1C]    ; esi = 0x45B1A570，血量对象 +0x1C
lea ecx, dword ptr ds:[esi+0x2A0]   ; esi = 0x45B1A2D0 → 0x45B1A570
mov eax, dword ptr ds:[esi+0xC8]    ; esi = 0x4555CC00 → 0x43103C78
mov ecx, dword ptr ds:[esi+eax*4+0x320] ; eax = 1 → 固定 +0x144
mov ecx, dword ptr ss:[ebp+8]       ; call 第一个参数；本例 ebp 为堆对象
mov ecx, dword ptr ds:[ebx+0x24]    ; ebx 来自 xajh.exe+0x11282D8
```

验算：`0x45B1A2D0 + 0x2A0 = 0x45B1A570`，再读 `+0x1C` 即为血量；把完整公式填入 CE 指针地址应读出相同血量。

## 变体与关联

- 变体：用内存写入断点代替访问断点，适合关注“谁修改血量”而不是“谁读取血量”；两者得到的对象和偏移可能不同，需要分别回溯。
- 变体：用 CE 指针扫描批量生成候选链，再用 x32dbg 验证；适合层数多、手工回溯易迷失的目标。
- 变体：同样的“搜数 → 访问断点 → 逐层回溯”可迁移到魔法值、金币、坐标等角色数据；偏移随游戏版本/区服变化。
- 关联卡片：[[code-analysis-reverse-windows-game-control-pointer-chain]]（同一套方法用于 UI 控件对象，侧重写断点、结构语义与遍历链）。
- 边界：`int 3` 区域、循环内假来源、`[ebp+8]` 的栈/堆判定是常见翻车点；64 位目标需改用 `rcx/rdx/r8/r9` 与 8 字节偏移。

## 检测与防御

- 从游戏安全/反作弊视角：检测 Cheat Engine/x32dbg 的进程与驱动、`ReadProcessMemory`/`WriteProcessMemory`、硬件断点寄存器 `DR0-DR7` 与 `int3`；对血量等关键数值做服务端校验、加密/校验和，避免客户端内存成为唯一权威。
- 从逆向工程视角：调试前记录模块基址与版本；每层用条件断点与真实数据校验，避免追到同名但不同来源的对象；操作后及时清理断点与恢复线程。
