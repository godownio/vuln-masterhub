## 一句话结论

在 32 位 Windows 游戏中，先用 Cheat Engine 按“输入 5 个 1 → 删成 4 个”的值变化锁定登录框的数据地址，再在 x32dbg 对该地址下写断点，沿“寄存器 ← 寄存器/内存”逐层向上回溯到模块基址与偏移，可得到当前激活小控件（输入框）的完整指针链；再对活动控件指针下写断点找到遍历循环，最后通过小控件 `+0x4c` 的大控件名和访问断点回溯出父级大控件结构。

## 原理

- **值扫描为什么要“移动光标”区分**：账号/密码框输入 5 个 `1`，搜索 5；删掉一个搜索 4 后仍可能有多个候选。此时不改变字符数、只移动光标，控件内容相关的地址不变，而光标位置/激活控件指针会变——那个“不变”的候选才是控件数据本体。
- **写断点回溯**：对候选地址下写断点，命中的指令形如 `add dword ptr ds:[esi+1E4], ebx`，说明数据来自 `[esi+0x1E4]`。往上一个调用帧找 `esi` 的赋值（常见 `mov esi, ecx`），再找 `ecx` 的来源，重复“看当前帧寄存器赋值 → 返回上一层 → 追 exx 来源”，直到某个寄存器等于模块基址或不再变化。
- **结构语义**：控件对象中常见固定偏移：
  - `+0x18` 存控件名（示例为 `Txt_Password`）；
  - `+0x4c` 存所属大控件名（示例为 `Win_Login`）；
  - `+0x15c` 存当前激活的小控件指针；
  - `+0x250` 是当前界面小控件的遍历链表/数组；
  - `+0x320` 是索引数组基址，配合 `ecx*4` 按下标取控件；
  - `+0x78`、`+0xc8` 是中间层指针。
- **为什么能追到大控件**：小控件归属于大控件，回溯到某一层后数据在不同小控件之间不再变化，说明已到达共同的大控件；此时读该层对象的 `+0x4c` 通常能看到大控件名，可用来确认。
- **索引与自引用指令**：遇到 `[esi+ecx*4+0x320]`、`[ebx+eax]` 这类含寄存器索引的地址，直接观察右侧数据不够，需要在当前行下条件断点（如 `[esi+ecx*4+0x320]==<目标值>`）才能命中正确的数组元素；`[ebx+eax]` 中 `eax` 往往来自循环，往上找 `ebx` 的赋值可确认它也是一个数组。
- **循环中的断点技巧**：循环内 `[eax+4]` 的值不好直接追时，可在循环外对 `eax` 下断，观察它是否始终不再变化；若只有一个来源，跳出循环找该来源（示例为 `[esi+0x250]`），能显著缩短回溯路径。

## 触发条件

- 目标为 32 位 Windows 游戏/应用，界面控件类数据在用户态内存中以对象+指针形式存在。
- 能使用 Cheat Engine 附加进程并读写内存；能使用 x32dbg（或同类调试器）附加并下断。
- 目标进程未启用会阻止附加/断点的强反调试，或已绕过反调试。
- 能正常操作登录框等控件，以便制造可控的值变化。

## 利用步骤

1. **锁定小控件数据地址**：在账号框输入 5 个相同字符，CE 搜索 5；删一个搜索 4；对剩余候选逐个“移动光标但不改变字符数”，值不变的那个就是控件内容地址。
2. **下写断点**：x32dbg 附加进程，对该地址下硬件/内存写断点，触发输入后记录命中指令与寄存器（示例 `add [esi+0x1E4], ebx`，`esi=20F33018`）。
3. **逐层回溯**：在当前帧找 `esi` 来源（`mov esi, ecx`），返回上一层继续找 `ecx` 来源；遇到多分支赋值时改用条件断点或在候选位置分别下断验证数据值。
4. **确认控件对象**：回溯到 `[esi+0x15c]` 一层时，跳到该内存看 `+0x18` 是否为控件名（如 `Txt_Password`），确认已定位小控件对象；同时记下 `+0x4c` 的大控件名。
5. **追到基址**：继续 `esi←ecx←[esi+0x78]←...←[esi+8]←[ebx+0x24]`，直到寄存器值为模块基址（示例 `0x1529788`），得到小控件指针链。
6. **找遍历循环**：对活动控件指针 `[base+0x15c]` 下写断点，回溯到 `[eax+4]` 所在的循环；若循环内来源复杂，跳出循环看 `eax` 的唯一来源（示例 `[esi+0x250]`），再沿同一结构回到基址，得到遍历链。
7. **找大控件**：读取小控件 `+0x4c` 的大控件名；对稳定的大控件指针下访问断点，回溯 `[esi+0xC8]`、`[base+0x24]`、`[base+8]`、`[base+0x320+eax*4]` 等层，得到大控件链。

## PoC

示例构建（32 位，地址与偏移仅对该版本有效，不可直接移植）：

```text
当前激活小控件数据：
[[[[[[0x1529788]+0x24]+0x8]+0x320+ecx*4]+0x78]+0x15c]+0x1E4]

小控件遍历：
[[[[[0x15282D8]+0x24]+0x8]+0x320+ecx*4]+0x78]+0x250]（链表循环）

大控件：
[[[[0x1529788]+0x24]+0x8]+0x320+eax*4]+0xC8]+ebx（ebx 来自 edi*4 数组）
```

关键回溯片段：

```asm
; 命中控件数据的写入
add dword ptr ds:[esi+1E4], ebx      ; esi == 20F33018
; 上一层
mov esi, ecx
; 再上一层：活动控件指针
mov ecx, dword ptr ds:[esi+15C]      ; esi == 35254700
; 结构中的控件名 / 大控件名
; [对象+18]  -> "Txt_Password"
; [对象+4C]  -> "Win_Login"
; 索引数组（需在该行下条件断点，例如 [esi+ecx*4+320]==353B92E8）
mov ecx, dword ptr ds:[esi+ecx*4+320]
```

CE 侧的操作序列：

```text
输入 11111 -> 搜索数值 5
删成 1111  -> 搜索数值 4
对每个候选：移动光标但不增删字符 -> 值不变者为控件数据
```

## 变体与关联

- 变体：用 CE 的指针扫描（Pointer Scan）先批量找 `base+offset` 链，再用 x32dbg 验证每一级；适合结构稳定但回溯路径长的目标。
- 变体：对列表类数据（角色列表、物品列表）同样可用“值扫描 + 写断点 + 数组索引 + 循环来源”定位遍历结构，与本卡控件链思路一致。
- 变体：64 位目标寄存器与调用约定不同（`rcx/rdx/r8/r9`），偏移宽度变为 8 字节，但回溯方法不变。
- 关联：与“列表类数据定位”（值扫描 + 写断点 + 数组索引 + 循环来源）同属一套指针回溯方法，可相互迁移；控件结构被混淆时可参考 `code-analysis/reverse/obfuscation` 下的还原思路。
- 边界：地址/偏移随游戏版本、编译选项、ASLR 变化；若控件结构被加密或指针校验，需先定位解密/校验逻辑，不能直接套用示例链。

## 检测与防御

- 从游戏安全/反作弊视角：
  - 检测 Cheat Engine、x32dbg 的进程名/窗口标题/驱动加载；检测 `OpenProcess`/`ReadProcessMemory`/`WriteProcessMemory` 与调试寄存器 `DR0-DR7`、`int3` 断点。
  - 对控件数据做指针加密/校验和，或在服务端校验关键输入与状态，避免客户端内存成为唯一事实来源。
  - 对异常频繁的输入值搜索与断点触发做行为监控；加壳/反调试只能提高门槛，不能替代服务端校验。
- 从逆向工程视角：调试前保存快照、记录基址与模块版本；每次回溯用条件断点验证数据值，避免把“恰好相同的值”误认为同一来源。
