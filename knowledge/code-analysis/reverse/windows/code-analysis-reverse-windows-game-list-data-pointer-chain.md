## 一句话结论

在 32 位 Windows 游戏中，对一个“能主动改变、界面立刻可见”的量（物品数量、NPC 名字）做 CE 值扫描锁定地址，再用 x32dbg 访问断点沿“寄存器 ← 寄存器/内存”逐层回溯，即可得到背包、仓库、周围 NPC 等列表数据的基址 + 多级偏移与数组索引；当回溯卡在无赋值的 `[esp+xx]` 时，用访问断点、CE 地址反查或 call 头部单步步过三种方法继续。

## 原理

- **突破口选择**：找一个攻击者能主动修改、且修改结果立即在游戏中可见的量——背包物品数量、仓库物品、NPC 名字、血量都行。先搜初始值，改变后再搜新值，反复筛到少数候选。
- **访问/写断点回溯**：对候选地址下断，命中的指令形如 `cmp dword ptr ds:[edi+70],1`，说明数据来自 `[edi+0x70]`；继续找 `edi` 的来源。若来自 `[esp+0x84]`，到堆栈区确认它是某个 call 的第几个参数，返回上一层找该参数（常见 `push eax`）。
- **数组元素与索引**：列表数据的地址通常是一个数组元素，表达式含 `eax*4`、`edi*4` 等索引缩放。回溯时要区分“数组基址 + 索引”与“对象内固定偏移”；同一款游戏的背包、仓库、NPC 列表往往共享前几层基址链，只是固定偏移和索引数组不同。
- **回溯断在半路的三种解法**（本文核心）：
  1. 对最后找到的数据下**访问断点**，看能否断出具体来源；
  2. 在 CE 中**搜索这个地址**，反查谁持有它；
  3. 到 **call 头部下断，单步步过**执行，盯有没有与目标数据相等或相近的值。
  文章在背包路径上前两种都没走通，第三种发现 `edi+8` 正是目标数据，再顺着 `edi` 的来源逐层回溯，整条链才串起来。
- **典型链**（地址/偏移只对该版本有效）：
  - 背包物品数量：`[[[[[[0x15282D8]+0x24]+0x90]+0x8]+0x14]+0x2C]+eax*4]+0x70`；注意取到 `edi` 后还要 `+0x8` 才是目标数据。
  - 仓库：`[[[[[0x15282D8]+0x24]+0x90]+0x8]+0x38]+0x2C`，与背包共享 `0x15282D8 → +0x24 → +0x90 → +0x8` 前几层。
  - 周围怪物 NPC 名字：`[[[[[0x15282D8]+0x24]+0xC]+0x74]+0xAC]+edi*4]+0x898`。
- **结构复用**：找到一类列表后，其余列表可顺着同一套基址/中间层去套；前几层重合是常见现象，但固定偏移、索引数组位置要分别验证。

## 触发条件

- 目标为 32 位 Windows 游戏/应用，列表数据在用户态内存中以“数组 + 指针”形式存在。
- 能使用 Cheat Engine 附加进程、读写内存；能使用 x32dbg（或同类调试器）附加并下断。
- 目标未启用会阻止附加/断点的强反调试，或已绕过。
- 能正常操作背包/仓库/NPC 等界面，制造可控的值变化。

## 利用步骤

1. **CE 锁定地址**：背包反复改变某物品数量；仓库反复放入同一物品；NPC 选中后改名。每次修改后重新搜索新值，筛到少数候选。
2. **下访问断点**：x32dbg 附加，对候选地址下硬件/内存访问断点，触发操作后记录命中指令与寄存器（如 `[edi+0x70]`、`edi` 来自 `[esp+0x84]`）。
3. **堆栈回溯**：到堆栈区确认 `[esp+xx]` 是哪个 call 的第几个参数；返回上一层找该参数的来源（`push eax` 等）；每一步先核对数据是否正确再继续。
4. **处理卡点**：若来源是全局 `[esp+xx]` 且上下找不到赋值，依次尝试访问断点、CE 地址反查、call 头部单步步过；找到相近数据后（如 `edi+8`）继续沿新寄存器回溯。
5. **形成偏移链**：把每层 `[reg+offset]` 串成基址 + 多级偏移，CE 的指针编辑器填入验证；对数组元素补上 `+index*4`。
6. **复用结构**：用同一基址链套仓库/NPC，按命中指令确认固定偏移与索引数组，逐项验证。

## 变体与关联

- 变体：先用 CE 指针扫描（Pointer Scan）批量找 `base+offset` 链，再用 x32dbg 验证每一级；适合结构稳定但回溯路径长的目标。
- 变体：64 位目标寄存器/调用约定不同（`rcx/rdx/r8/r9`），偏移宽度变为 8 字节，但回溯方法不变。
- 变体：列表数据被加密/混淆时，先定位解密或校验逻辑；指针加密、校验和会让直接偏移链失效。
- 关联：[[code-analysis-reverse-windows-game-control-pointer-chain]]（同一套 CE + x32dbg 指针回溯方法，对象是 UI 控件/父级大控件）；[[code-analysis-reverse-obfuscation]] 系列用于结构混淆。
- 边界：地址与偏移随游戏版本、编译选项、ASLR 变化，不能直接移植；反调试/指针校验会阻断附加或让链失效。

## 检测与防御

- 游戏安全/反作弊视角：
  - 检测 Cheat Engine、x32dbg 的进程名/窗口标题/驱动加载；检测 `OpenProcess`/`ReadProcessMemory`/`WriteProcessMemory` 与调试寄存器 `DR0-DR7`、`int3` 断点。
  - 对背包/仓库/NPC 等列表数据做指针加密、校验和或服务端权威校验，避免客户端内存成为唯一事实来源。
  - 监控异常频繁的值搜索、断点触发与对列表区域的批量读写。
- 逆向工程视角：调试前保存快照与模块版本；每次回溯用条件断点/数据值核对，避免把“恰好相同的值”误认为同一来源；结构化记录每层偏移，便于版本更新后重新定位。
